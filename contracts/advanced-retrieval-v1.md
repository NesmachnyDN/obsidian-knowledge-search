# OKS-05D — Offline Advanced Retrieval, model-envelope protocol v4

**Status:** Candidate for independent SDD review. Implemented in `engine/advanced_retrieval.py`, `plugin/src/advanced/model-protocol.ts`, `plugin/src/advanced/retrieval*.ts`; requires explicit Advanced opt-in. This document **does not replace** canonical document Source/Evidence ingestion protocol v3 (`contracts/advanced-ingestion-v1.md`) or the health-only transport v2. Standalone is unchanged and never requires Python or model artifacts.

## Model identity and offline profile

The model is local `BAAI/bge-m3`, pinned revision `5617a9f61b028005a4858fdac845db406aefb181`, upstream MIT license; exact tokenizer and weight SHA-256 from `engine/tokenizer-artifacts.json` and `engine/embedding-artifacts.json`. The dedicated opt-in worker uses the verified CPU-only PyTorch/Transformers runtime, CLS pooling followed by unit-L2 normalization, and `bge-m3-heading-lines-v1` serialization, with no remote code and no downloads. Query and document embeddings must match **every** identity field including effective token limit, tokenizer digest, weights digest, runtime versions, pooling and serialization. Output dimension is 1024, all elements finite, norm within 1e-4 of 1. No hash vectors or substitute model are valid.

Exact v3 chunk tokenizer fingerprint includes the complete tokenizer-only serialization identity and is intentionally **not** the raw tokenizer file hash. The Python tokenizer verifies original v3 chunk construction; the TypeScript `CHUNK_TOKENIZER_FINGERPRINT` constant binds to its frozen current identity. A change in the tokenizer manifest requires a new reviewed fingerprint and index rebuild. Neither process silently truncates document/query text. Chunking is upstream v3 tokenizer-aware at a bounded 384-token effective limit; oversized inputs fail explicitly. One-shot request batches are bounded by 64 texts, 8192 UTF-8 bytes/text and total 32768 full-input tokens. Index scope: at most 32 explicitly selected sources, 64 chunks/source, 256 indexed vectors overall; minimum 1, maximum 50 returned hits. A source exceeding bounds returns a typed refusal.

## Strict model worker envelope

Single canonical JSON line request/response; UTF-8, Unicode-codepoint-sorted JSON keys, ECMAScript-compatible finite JSON numbers, no duplicate keys, BOM, nested junk, unknown fields, or multiple lines. Requests max 128 KiB and responses max 8 MiB. All values exact typed.

Request fields: `protocolVersion: 4`, `requestId: [a-f0-9]{48}`, `operation: "embed"`, `deadlineUnixMs: positive safe integer`, `modelSnapshot: absolute verified local directory`, `maxTokens: integer 8–512`, `texts: 1–64 nonempty UTF-8 strings`. Worker enforces 120-second bounded deadline and full-token limit without padding/truncation. Response exact fields: `protocolVersion`, `requestId`, `operation`, `status: ok|failed`, `error`, `identity`, `vectors`, `diagnostics`. A failed reply must have no vectors or identity. Success must have one validated 1024-D vector per requested text, matching nonce and model identity. An absent/incompatible model is an explicit failure. A health-v2 `ready` response cannot fulfill a model request.

The existing hardened cgroup v2 supervisor is reused: 4 GiB MemoryMax, MemorySwapMax=0, 200% CPUQuota, TasksMax=64, max 120s, host memory reserve of 2.5 GiB, ≥1 GiB free disk, `RestrictAddressFamilies=AF_UNIX` plus verified AF_INET socket denial, environment-level Hugging Face offline flags, whole-unit cancellation/cleanup. No implicit limit increase, no remote content, and no model work on Obsidian's UI thread. Any violation fails closed.

## Retrieval identity, ranking, and evidence

The durable retrieval snapshot is **separate** from the Standalone index and references the immutable v3 source record and v3 chunks rather than copying canonical Source/Chunk/Evidence definitions. Each entry binds `sourcePath`, SHA-256, v3 `ingestGenerationId`, `profileId`, full tokenizer fingerprint, ordered v3 chunk IDs and ordered 1024D vectors. The generation ID is the SHA-256 of canonical JSON over `{schemaVersion:1, rootId, model, entries}`; entries sorted byte-stably by path and duplicated paths forbidden. Atomic private XDG stage/fsync/rename publication through `CURRENT` preserves last authenticated generation, and cold open checks manifests, pointer, lengths and all vector norms. If an initial publish is canceled or crashes **before the first CURRENT** is created, a cold open authenticates every leftover derived generation against root/model/chunk IDs and discards only known unpublished derived generations and safe stage files; none becomes searchable, and indexing can be retried. A present corrupt CURRENT, malformed orphan or symlinked stage still fails closed without cleanup of unknown bytes. Disagreement requires explicit rebuild; it is never silently used.

For dense/hybrid, both legs receive the same eligible **model-indexed** original-source universe; a separately ingested but unindexed document is not an implicit candidate. An explicit scope containing a known eligible unindexed document returns an unavailable result, not a partially successful hybrid. A scope with no matching sources returns a valid zero-hit response when the model and index are healthy. Every indexed source is authenticated against the current v3 ingestion record before scoped filtering, so an excluded stale indexed source cannot disguise incompatible generations. Lexical-only mode may search all verified ingested sources. Vault-relative scope and typed Properties predicates filter **before** Top-K, per-mode ranking and evidence projection. Lexical reuses Standalone's technical identifier preservation, RU/EN casefold-like tokenization and typed comparison, with exact compound identifier boosting and a stable chunk ID tie-break. Dense embeds the actual query with the pinned model, scores unit vectors with dot product, and sorts by descending score/ascending canonical chunk ID. Hybrid executes **both** independently, and applies Reciprocal Rank Fusion `sum(1/(60 + per-leg-rank))`, merging by v3 canonical chunk ID; ties resolve ascending canonical chunk ID. Missing or failed required leg returns `status: failed`, `executedMode: none`, no hits and explicit error. No fallback to lexical under a dense/hybrid request.

Retrieval response v4 exposes `requestedMode`, `executedMode`, `status`, `indexGenerationId`, `legs.lexical` and `legs.dense` with separate status/error/candidate counts, verified hits and `staleSourceCount`. A hit includes v3 `sourceId`, `vaultRelativeReference`, SHA-256, `chunkId`, original `originalExcerpt` with source locator from v3, original extraction status including `partial`, retrieval mode/rank, lexical rank/score, dense rank/cosine similarity and RRF score. A contextual embedding input is **never** exposed as original evidence. Source-native page/geometry and DOCX table-cell locators are kept exactly as v3; no synthetic pages, offsets or line numbers. If no verified original locator is available, omit the candidate rather than create a hit.

Before publication, after inference, before returning a result, and before navigation, source hashes and generation identities are reverified against descriptor-anchored raw Vault TFiles. An in-flight invalidation revokes the source and cancels indexing/search; stale, renamed, removed or unauthorized sources are excluded, and an incompatible hybrid generation fails wholly. On Markdown navigation, verify raw bytes and actual excerpt byte-span and open/select through supported Obsidian APIs. Native PDF/DOCX use Obsidian's supported file opening, without claiming guaranteed native page/cell selection when the public API cannot provide it.

## States, limitations and acceptance

States distinguish opt-out/disabled, model unavailable/not-ready, active indexing/search, readiness and failed/refused. `ready` dense requires authenticated vectors in an eligible compatible snapshot **and** a successful real query leg, not only model load or transport health. Initial implementation explicitly indexes active files one at a time and supports an explicit incompatible-generation rebuild; it does not automatically scan a user Vault or alter notes. Per-query model cold start can dominate latency; performance must be measured rather than called satisfactory. The 05D snapshot design is per-source with bounded volume, not a vector database or unrestricted enterprise-scale collection.

Minimum acceptance: real forward pass, cross-language v4 schema checks, exact-ID and bilingual queries, synthetic retrieval metrics, adversarial forged source/vector/freshness/lineage cases, cgroup resource and descendant cleanup, restart/corrupt-current rejection, two independent real Obsidian Desktop/CLI 1.15.1 **no-route** contours, plus existing SDD checks. Release/phase gate remains blocked without separate-session full-diff independent review and exact-HEAD CI. See `docs/prompts/OKS-05D.md`.
