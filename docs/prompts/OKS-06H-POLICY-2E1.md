# OKS-06H-POLICY.2e1 — bounded exact-version lifecycle transitions

Base: `b5d6ed21a0b0106d76dfa99e0a6767b1089cd4e2`. Issues #78/#79/#105; AC-11-POLICY-02/03; ADR-0019/0021; ROADMAP POLICY.2 and POLICY.2e. Standard bounded implementation slice.

Extend the existing `NewMaterialTracker` only. Add pure, bounded exact-version lifecycle transitions and an explicit initial-baseline preview/one-shot-confirmation protocol. Preserve its existing runtime methods and behavior. A baseline preview binds root, complete exact bounded candidate set, rules revision, trusted host/session, expiry and one confirmation; it excludes known verified-new or ambiguous paths. Confirmation must revalidate every binding and candidate and admit all-or-nothing. Root/scope/rules/owner/event/candidate/replay/expiry mismatch denies without partial admission.

Add a separate canonical-reader lifecycle proof API from one protected descriptor read, without changing `OriginalVersionProof`. It supplies an opaque domain-separated root/device/inode/birth-time identity and rejects an absent/nonpositive birth time. Positive observed birth time alone does not establish a filesystem support guarantee; production integration must independently admit the host identity semantics and fail closed otherwise. Stable identity alone never advances continuity. Advancement requires the exact prior version, same native owner, a fresh canonical proof, a new unambiguous transition event and matching stable identity evidence even for identical bytes. Exact verified single-file rename may carry continuity; delete retires the prior version, and a distinct trusted creation may admit a new version. Collision, uncertain rename/folder move, overflow, owner ambiguity, missing/out-of-order/replayed events and restart remain unresolved. The host supplies a gap-free monotonic event sequence and explicitly complete inventory; this pure substrate cannot prove production event ordering or inventory completeness. Baseline is one per in-memory epoch, never a durable restart admission.

Out of scope: main/Obsidian integration, native event trust/verification, durable ledger/anchor/storage, source writes, provider admission or egress, imports and production-Vault use. The trusted host is the caller boundary; no note data mints evidence. This slice makes no claim that a production native event has exact-version trust. Durable restoration and production event verification are deferred to POLICY.2e2/2e3.

Tests use isolated synthetic files only and cover unchanged/modified/replaced same-byte/renamed files plus positive and adversarial transition and baseline cases. No dependencies, network, model, credentials or repository/GitHub mutation. Run TypeScript checking and focused/full Node tests. Record unresolved limitations in the handoff.
