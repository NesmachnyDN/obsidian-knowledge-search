## Linux host isolation and observed environment limits

Keep the existing no-route namespace mode as a first-class path. On Linux test host, unprivileged `unshare -Urn` maps system root-owned /tmp and /usr to UID 65534, while the actual durable directory and flock primitives intentionally require trusted UID ownership. Neither primitive may be weakened to admit this artificial environment. Direct `unshare -n` is unavailable without privilege.

For this synthetic lifecycle-only test, a separate opt-in Linux x86_64 direct-network-denial mode may use the already installed libseccomp runtime through the standard Python library; no install, privilege escalation, global network change, or production dependency. It preserves real filesystem UID semantics, creates a private disposable profile with umask 077, strips the credential/proxy/desktop environment, closes inherited non-stdio descriptors, requires non-socket stdio, denies non-Unix socket families, io_uring and pidfd_getfd in an inherited kernel filter, and verifies TCP/UDP IPv4/IPv6 creation denial before launch and from an actual renderer child. Unix IPC remains available for X11 and Obsidian CLI. This is direct-network denial for a trusted synthetic test, not a network namespace, hostile-program sandbox, IPC-relay proof, or evidence of provider/no-route acceptance. Do not enable another host scenario, a real provider, or a real Vault under this mode. If the isolation check fails, abort. Report the exact mode and distinguish positive capability evidence from fail-closed unavailability. No production authorization follows either result.

Both isolation modes must preserve the existing security boundaries. Initial evidence in `build/acceptance-evidence/policy-2e3a-host-admission/`: namespace negative (UID remapping); real-UID synthetic direct-network mode originally rejected group-writable XDG ancestry (0775); private profile (0700) permits the actual ledger. These are harness findings, not authorization to change production directories or bypass admission.
