# OKS-06H-POLICY.2e — durable lifecycle design and dependency-ordered delivery

Base: `cafe1f35aa3ad8b215e365dbec66af490dd8bc9e` (accepted POLICY.2d #117). #79/#78/#105; AC-11-POLICY-02/03, ADR-0019 and proposed [ADR-0021](../adr/0021-durable-material-lifecycle.md). DOCS_ONLY first: independently review baseline admission and storage threat boundary before functional changes. Preserve strict pilot, Basic and Graph acceptance. No provider, production Vault, source writes or new platform claim.

**Historical execution contract:** ADR-0023 prospectively supersedes marking-specific dependencies for read-only consumer policy; preserve prior accepted evidence and current authority defenses, and reconcile before further implementation. No automatic retirement of security gates. See [rebaseline](OKS-06-REBASELINE.md).

1. POLICY.2e1: extend the existing tracker with bounded exact-version transitions and explicit initial baseline preview/confirmation semantics, test pure lifecycle invariants and canonical original-reader identity evidence. No production integration, durable backend or note writes. Keep version proof separate from identity continuity and authorization.
2. POLICY.2e2: select and validate a host-private durable ledger backend with strict versioned schema, trusted current commit anchor, exclusive writer, atomic crash-safe publication, bounded recovery and descriptor-safe IO. Reuse existing primitives; do not trust lexical index as provenance. Test stale snapshots, tampering, foreign root, corrupt/partial commits, resource bounds, concurrent host instances, lock/restart recovery; do not claim production trust from mock anchors. No new Basic prerequisite.
3. POLICY.2e3: wire ledger/tracker into native lifecycle, baseline UI and all existing shared processing-policy roles. Use canonical exact original proof on restoration and before every applicable policy use; same-byte replacement cannot evade classification. Keep single authority, revoke before observers, fence async work, preserve physical drain and deny stale grants. Test actual isolated Obsidian lifecycle, including restart and rule changes. Do not enable provider/egress.
4. POLICY.2f: trusted import adapter, verified version-bound source/channel provenance and distinct known non-import/unknown semantics.
5. POLICY.2g: separately enabled governance-aware idempotent writer and local lifecycle completion, verified atomic version-bound update, re-read and rule re-evaluation; no mass writes or production Vault tests.

Each functional slice requires a pinned bounded execution contract, independent exact-HEAD full-diff review, all applicable SDD gates, guarded merge and post-merge regression. The design PR does not certify any runtime behavior, select an unverified persistence backend or close #79/#78/#105. If a capability cannot be proved, retain unresolved and continue only admissible independent work.
