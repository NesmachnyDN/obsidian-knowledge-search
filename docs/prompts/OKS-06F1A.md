**Workflow:** DOCS_ONLY, bounded slice of #107 (parent #105); baseline `ac7a7862da689821e550ade83901268c23a5002c`. ## Current implementation audit

| Boundary | Actual reference implementation | Portability obstacle / target seam |
|---|---|---|
| Host composition | `plugin/src/main.ts` creates BoundedVaultReader, GenerationStore and WorkerMarkdownParser; depends on FileSystemAdapter, Node path/crypto and desktop services | Isolate platform composition; a mobile bootstrap must have no eager or transitive desktop imports. Keep one logical plugin and existing manifest desktop-only until the real mobile gate passes. |
| Source and scope | `plugin/src/standalone/source.ts` SourceProvider (list/versionHints/read); BoundedVaultReader authenticates root and descriptors | Extract only the existing provider contract and capability evidence. A mobile provider must prove authoritative uncached bytes, scope, exclusion, size bounds and identity; cache, path, digest or events alone are not continuity. |
| Canonical data | `plugin/src/standalone/shared.ts`, `plugin/src/standalone/contracts.ts`, `plugin/src/standalone/markdown-parse.ts`, selection and metadata verification | Parsing already uses typed arrays and Web APIs; contracts use Node crypto/Buffer. Keep serialization and SHA-256 parity, UTF-8 bytes and original locators; isolate hash/byte encoding without a second schema or a second search engine. |
| Storage | `plugin/src/standalone/storage.ts` GenerationStore load/commit, filesystem staging, current pointer and recovery | Derive a narrow structural generation-store port from actual engine use; preserve root binding, validation, atomic visibility, cancellation, previous-generation recovery and safe purge. |
| Worker | `plugin/src/standalone/worker.ts` MarkdownParser/PolicyMetadataParser and WorkerPort, Node descriptor asset loading; `plugin/src/standalone/worker-entry.ts` browser worker | Separate verified packaged asset loading from the worker transport and protocol. No main-thread parser fallback, remote script or source execution. |
| Scheduling / optional services | `plugin/src/standalone/engine.ts` bounded queue, shared physical slot; `plugin/src/ai/active-deadline.ts`, `plugin/src/advanced/runner.ts`, `plugin/src/supervisor.ts`, `plugin/src/ai/loopback-json.ts`, lifecycle ledger/lock and search settings use desktop facilities | Separate cancellation, resource sampling, process supervision, network and lifecycle proof capabilities. Optional desktop services must not enter the mobile load graph. |
| Build | `scripts/build.mjs`: Node/CJS main plus browser worker; `plugin/manifest.json`: isDesktopOnly=true | Future browser-safe build audit and equivalent verified package identity; not a manifest-only change. Existing three-asset desktop package is not proof of Community Directory distribution compatibility. |

## Proposed responsibility and compatibility contract

- Keep the one canonical source/version/scope, typed metadata, index and evidence model. Introduce only the seams required by the existing callers, not a parallel engine or new service. Compose host-specific source, generation store, hash/byte utilities, worker asset/port, scheduler/resource/clock, navigation and optional transport/process providers behind explicit capability checks. A capability is unavailable until its platform-specific proof passes. Use deterministic cross-host fixture parity for canonical digests, Unicode/CRLF, block and property semantics, exact byte/character/line locators, scope and errors. Web Crypto async hashing is a candidate: design the actual call chain and parity before changing synchronous digest APIs; do not silently substitute a different hash or serialization.
- Desktop Linux retains its descriptor-root, private storage and publication protections; Windows/macOS need separate authenticated filesystem and atomic storage/locking/rollback evidence (including reparse points, case/Unicode aliases and platform permissions as applicable). Do not emulate unsupported POSIX guarantees by a successful ordinary read.
- Mobile candidate: use supported Vault/DataAdapter and Web APIs, fresh reads rather than MetadataCache/cachedRead for authority. Demonstrate a bound **before** allocation or a proven bounded streaming equivalent, authenticated logical root and exact current version with revalidation before publication and navigation. The existence of readBinary and a size/stat hint is not sufficient proof; if no safe mechanism exists, the relevant source operation and Gate A remain blocked. Never trust a caller-supplied path, silent truncation, or partial inventory as complete.
- IndexedDB in the app WebView is a candidate for host-local derived generations, not an accepted backend. Prove private non-synced storage, per-vault namespace and root authentication, schema/version and size validation, single-writer/fencing across reloads, durable transaction/commit and recovery, quota failure and disabled-only purge. An origin or vault display name alone is not root authority. If the host cannot establish these properties, leave durable publication unavailable and do not claim Gate A. No parsed-cache transfer through Vault sync.
- Maintain one active physical worker/queue; cancel and fence stale generations and late callbacks on source change, suspend, low memory, disable/unload and root changes; prove kill/reopen recovery. Never classify material as existing/new from restart, path, hash or missing event. Durable material lifecycle, writer, import and processing admission (ADR-0021/0019) remain separate; Basic does not require them. Corpus eligibility (ADR-0022) is not access or egress permission; optional AI remains unavailable until its exact host/role gates pass.

## Frozen baseline constraints and further proof gates

For portability pilot acceptance preserve the existing `BOUNDS` (64 KiB source, 512 sources, 32,768 blocks total, 4,096 per source, 16 MiB generation, 512-byte query, Top-K 50 and all remaining metadata/inventory limits), one worker and bounded cancellation. A smaller host budget may deny with a typed failure; it cannot silently omit sources or weaken scope. Gate A must not require AI, Python, provisioning, paid service or network. Use the existing 05E cumulative matrix, frozen synthetic RU/EN corpus and negative fixtures; zero stale/fabricated hits, unauthorized writes, egress, scope escape or misleading ready status. Record exact device/OS/app/architecture, cold and warm p50/p95, peak memory, index/disk size and recovery; report measurement method and failures. Do not invent a platform SLA from Linux timing. Before implementation of a platform-specific slice, freeze its measured resource admission/latency targets, supported version range, bounded-read and storage feasibility, and real-device test contract in a reviewed follow-on. No increased production capacity claim in this design.

Additional acceptance: inspect mobile build/load graph for Node/Electron imports and runtime globals, verify package and worker assets offline, real suspend/resume and process kill during pending read/commit, quota/resource pressure, conflicting reloads, missed events, sync replacement, touch navigation, clean uninstall/purge/rollback with original hashes unchanged. For desktop preserve 05E evidence and add platform-specific escape/locking/permission and process-tree cancellation tests. No Gate B/C inference from A.

## Managed optional runtime and distribution

Current upstream policy checked 2026-11-27: [Community Directory developer policies](https://docs.obsidian.md/community-directory/developer-policies) prohibit plugins installing/updating themselves or dependencies; [mobile development](https://docs.obsidian.md/Plugins/Getting%20started/Mobile%20development) identifies missing Node/Electron APIs; [submission requirements](https://docs.obsidian.md/community-directory/submission-requirements-for-plugins) and [release instructions](https://docs.obsidian.md/Plugins/Releasing/Submit%20your%20plugin) constrain the release shape. These are policy evidence, not listing approval. Existing desktop worker asset and naming/manifest requirements need separate distribution validation before release.

Evaluate independently: (a) external signed platform installer/package manager with explicit user initiation (preferred design candidate; plugin only discovers/verifies readiness); (b) approved prebundled optional assets where distribution rules allow, measuring footprint; (c) private distribution with an explicit installer boundary, not a Community Directory compliance workaround. Reject plugin self-updating/download/install of dependencies. No implicit installer launch, command interpolation, elevated privileges or consent bypass. On first explicit unsupported document request or settings action show supported platform, pinned component identity, size/disk requirements, publisher/license and offline processing boundary; decline leaves core working. The external mechanism must stage, authenticate, verify hashes/signatures and compatible versions, preflight resources, activate atomically, roll back, repair and remove safely. Plugin discovery accepts only reviewed trusted installation identities and does not execute arbitrary binaries. Resume the intended job only after readiness and current scope authorization. If unavoidable platform prompts or distribution rules prevent the intended one-action experience, report limitation and obtain product decision before claiming CAP-15.

06G.1 (#108) selects the extraction dependency set jointly with 06F.1; do not choose Java/LibreOffice, Python package versions, models or OCR assets here. 06D provides verified cache reuse. 06F.2 follows those prerequisites; 06F.4 may proceed after the complete 06F.1 design independently of desktop packaging, not after this partial audit alone.
