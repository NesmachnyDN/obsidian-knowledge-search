## UI, source navigation, and API choices

- Use public `Plugin.registerView`, `ItemView`, `Workspace.getLeaf/setViewState`, `Plugin.addCommand`, `Plugin.addSettingTab`, `Setting`, `Notice`, `Vault.getAbstractFileByPath`, `Workspace.openLinkText` or `WorkspaceLeaf.openFile`, `MarkdownView.editor` cursor/selection APIs, public DOM `textContent`/Obsidian safe text creation. No HTML injection, executable Markdown, unsafe `innerHTML`, path-name fuzzy resolution or DOM-heavy unlimited result display.
- On every result navigation verify exact vault-relative path, `TFile` identity, source version SHA-256 against fresh bounded no-follow bytes, and original locator byte/codepoint/line/excerpt before opening. Re-check after await and fail rather than navigate approximately; handle CRLF, emoji, Unicode and rename/delete. Filesystem-symlink boundaries are enforced by the existing reader. A stale hit is never advertised as current.
- Search UI input is bounded by existing protocol v2 (512 UTF-8 bytes, Top-K <= 50). Prevent stale asynchronous response painting via monotonically increasing UI request revision. Typed Property filters must create valid v2 predicates; invalid input has visible diagnostic and never silently coerces. Empty query shows neutral guidance. Status includes real generation/counters/reconciliation/errors/maintenance and explicit unavailable dense/hybrid.
- Define stable documented `OKS Standalone API v1` (UI/plugin in-process interface), strict envelope parsing/errors and result/version semantics using native protocol v2, supporting Obsidian CLI `eval` as verified local developer bridge, **not** an HTTP/remote IPC service. Do not assume unsupported CLI commands. Avoid exporting raw source or Properties via default diagnostics.

## Settings, lifecycle, safety

- Versioned sanitized settings with safe migration from the v1 fixture-only probe fields; opt-in advanced backend stored as configuration only, disabled by default, no auto-connect. Search/index enable and pause/resume/cancel/rebuild; initialization and dispose idempotence and async race protection; no multiple concurrent workers. Controls never delete source files. Only allow manual derived-only purge with explicit confirmation, stopped engine and identity-checked cache directory; retain failure diagnostics.
- Startup, load-before-layout-ready, reload, unload, worker failure, unreadable/corrupt index, recovery, cancel-during-publication and disabled settings must not leak evidence or misreport ready. No logs/exports of content, typed Properties, credentials, full absolute private paths, index blobs or user note text. No automatic network egress or background heavyweight process.
