# POLICY.2e3b — committed lifecycle restoration and origin retention

Base: `d081ce61db619a852173abbd09ecde5242e1f49e`. Authority: AGENTS, SECURITY, SDD, SPEC AC-11-POLICY-02/03, ROADMAP POLICY.2, ADR-0019/0021, POLICY.2e/2e1/2e2/2e3a; issues #78/#79/#105. Standard bounded slice. Reuse the existing NewMaterialTracker, BoundedVaultReader and DurableLifecycleLedger. No competing authority, new public plugin API, production wiring, source writes, provider, baseline UI or grants. Strict pilot remains unchanged.

Implement an explicit one-shot restore path on the existing tracker for a pristine opened lifecycle context, using the actual opened ledger and canonical reader, never a caller-provided snapshot or index/hash/metadata claim. Require admitted host-owned current-context fence with a captured one-shot AbortSignal and synchronous native owner resolver supplied by the future host integration; the host must synchronously abort that signal on every authority loss (including transient loss), never reset or substitute it; document these trusted preconditions, no claim of native authenticity. Capture context before asynchronous work; any exact lifecycle event, rule revision, clear/unload, incompatible legacy use or loss of host fence during restore prevents publication. No exact authority or baseline preview while restore is pending. No replay/second restore into a previously used tracker; no reset of baseline flag. Missing anchor, read/validation/lock failure or foreign root seals/denies recovery; never initialize or rebaseline automatically.

For each authenticated active ledger record, resolve exact native owner, freshly read the canonical descriptor lifecycle proof, and require equality of full root/path/content/version and stable identity, not same digest or inode. Recheck owner and current context after awaits and before synchronous publication; missing/changed/ambiguous record or owner remains unresolved with a conservative tombstone; preserve existing tombstones, reject duplicate active owner ambiguity rather than choose. Bound all work by the existing ledger/source limits. Recheck committed anchor unchanged immediately before publication; future trusted host must serialize restore with ledger writes/close and use fresh proofs on every policy-use boundary. Failed or cancelled restore cannot leave partial authority. Native events are not proven complete/authentic by this slice; no advancement based on restart/missing events.

Retain origin and originVersionId for exact admitted records through verified in-session advances and restoration; baseline flag is restored even where exact records no longer match, and pending new records must not become existing through baseline preview. Provide bounded immutable evidence export from the same tracker for future host-authorized ledger commits if needed, not authorization or an automatic persistence side effect. Do not silently drop unresolved/tombstone records. Keep accepted ephemeral and exact transition behaviors except stricter fail-closed restoration.

Acceptance: focused real Linux filesystem and actual ledger close/reopen tests (synthetic only), exact unchanged record and current owner, same-byte replacement, edited original, moved/missing original, wrong root/owner, duplicate owner, absent/corrupt anchor, baseline flag, pending new/tombstone protection, origin retention over transitions, interruption (event/rules/unload/host fence including false-to-true transient loss, signal substitution and pre-aborted signal), no partial publication/retry, bounds and existing regression. Host smoke 2e3a remains capability-only. This slice is a restoration integration primitive, not production admission: production startup/close serialization, event fencing, baseline UX and shared-policy boundaries remain separate mandatory 2e3 work. Fix no unrelated code; preserve Basic/Graph acceptance. Record known transient disposable host profile cleanup race without misreporting functional evidence.
