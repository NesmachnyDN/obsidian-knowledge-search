# POLICY.2e3e.1 — guarded durable publication of one live transition

Base: `1bbbb7898f71b2d12926be767139e91ebdc8ef40` (accepted #129). Authority: `AGENTS.md`, `SECURITY.md`, SDD, SPEC AC-11-POLICY-02/03, ARCHITECTURE, ROADMAP POLICY.2, ADR-0019/0021 and the preceding POLICY.2e contracts. This is a bounded host-private prerequisite, not a native lifecycle integration.

## Contract

Expose one pure, guarded ledger delta contract for a future trusted owner. It accepts an exact currently committed anchor, one delta (`create`, `modify`, `rename`, or `delete`), and the existing `signal`, `current` and asynchronous `revalidate` predicates. The substrate is not evidence that an Obsidian event is authentic, complete, ordered, or owned; it does not create lifecycle authority, classification, a grant, or a production caller.

The physical exclusive ledger lock remains held through observation, validation, publication and drain. The expected anchor must still be the sole committed CURRENT record. Derive the successor only from that committed snapshot: it must be an admitted baseline epoch, increment exactly one revision, retain epoch/root/baseline fact and leave every unrelated record byte-for-byte equivalent. Capture caller values before async IO, validate the bounded immutable schema, revalidate before CURRENT, and atomically switch CURRENT only after the final synchronous current fence. Failure before the switch denies. A throw after a switch attempt has typed `uncertain-publication`; it never asserts rollback.

Legal deltas are deliberately narrow. Create may install only one `verified-new` record with `native-create` provenance and its own exact origin version, at an absent or tombstoned path; it cannot replace an admitted or ambiguous record. Modify requires the committed prior descriptor proof, same path and stable descriptor identity, and a distinct canonical version ID. Rename requires the committed prior proof, a different unoccupied target path, stable descriptor identity and a distinct canonical version ID; it replaces only the old record with its tombstone and the preserved-state/provenance successor. In accordance with POLICY.2e1 and ADR-0021, the digest may remain unchanged: a fresh same-byte version of the same descriptor or an ordinary rename is not a same-byte replacement. An unchanged exact version is not a new durable delta. The future trusted owner must independently prove the event and fresh canonical proof. Delete requires the exact committed admitted prior and creates only its tombstone. No same-byte replacement, collision, ambiguous replacement, replay, stale anchor, unverified rebaseline, or tombstone resurrection outside the separate verified-create delta is legal.

No tracker, native owner, provider, egress, writer, production Vault, installed-plugin change or source mutation is included. A later owner integration must prove each native transition and revalidate current source/owner/rules/event state around this substrate; inability to prove those conditions remains unresolved.

## Acceptance

Use synthetic Linux vaults and the real ledger backend to test modify, rejection of stale/replayed/invalid deltas, same-byte replacement, collision and ambiguous replacement, guarded cancellation before CURRENT, revalidation failure, post-switch uncertainty, reopen recovery and no unrelated record change. Preserve the existing unguarded ledger methods solely for prior substrate tests. Run typecheck, build and focused tests when feasible. If sandbox UID or `flock` prevents the real-ledger runtime tests, report that limitation without weakening lock or publication checks. Implementation workers may not commit, push or merge unless separately delegated; the authorized SDD orchestrator delivers only after applicable gates, including independent exact-HEAD review.
