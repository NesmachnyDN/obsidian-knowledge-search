# OKS-06 P0.2b1 — suppress incompatible restored lexical generations

Base: 3b069adca10240e61f460bec8b2d34c3dd0fdfee. Authority: ADR-0023, CAP-01, AC-01/06/08/10, #105, #146 and OKS-06-P0-HARD-SCOPE-1. Prerequisites: accepted immutable standalone source scope; native effective policy is accepted separately in #148.

Reuse the exact immutable hard scope captured by BoundedVaultReader; expose it read-only to the existing StandaloneEngine, with no second scope configuration or authority. On authenticated CURRENT or rollback recovery, never install a generation containing a hard-excluded source even transiently, including status/counts, lexical search and graph/chat/dense leases. Keep the engine initializing with no generation and run a complete scoped reconciliation, without reusing old documents. Do not treat an unknown/unauthenticated store as safe. Guard the new generation before publication. Keep the historical unscoped/empty-scope behavior. The existing store may retain authenticated rollback bytes as private derivatives; every scoped restart must reject incompatible restored generations. This slice is logical visibility isolation, not physical cache cleanup or complete hard scope acceptance.

Use existing store, parser, retrieval and source owner; no new dependencies, storage schemas, parallel active index or changes to original bytes. Tests: existing unscoped CURRENT and corrupted CURRENT with authenticated rollback containing excluded notes; gated reconciliation proves no generation/records/Basic hits or dense/chat lease before publication; cancellation and restart preserve denial; allowed sibling only after scoped publication, direct selection of excluded note remains denied. Test restart of scoped generation with incompatible rollback. Preserve recovery semantics for empty/unscoped sources. Synthetic fixtures only. No real Vault, provider, producer, heavy indexing or release.

Out of scope: persisted settings/UI and live atomic owner replacement, scope revision binding of AI/history/graph authority across instances, physical retirement/cleanup of old derived caches, Advanced and all-owner attachments, automatic AI corpus, actual platform or provider acceptance. The next dependent slice integrates those boundaries. Standard typecheck/build, focused tests and complete CI, independent exact-base/head review before merge. #105 remains open.
