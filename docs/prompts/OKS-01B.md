# OKS-01B — Runtime and storage foundation

Base: 60680ab636d58d40b55bc2c6d723c41af3dac7f1 (OKS-01A merged). Profile: PHASE_CLOSE. Authority: AGENTS, SPEC CAP-01/08/09 and AC-01/08/09 (partial), ARCHITECTURE resource/freshness obligations, ADR-0001/0002, ROADMAP, REUSE, SECURITY and SDD. Foundation exit: tested design and protocol, no unresolved blocker to the next synthetic slice. This is not full capability, workload or production-vault acceptance.

## Scope and design gates

Use Python 3.12 standard library and installed SQLite/FTS5; no model, tokenizer, parser, vector extension download or server dependency. Independently authored, tiny deterministic synthetic inputs only. Do not change the working Obsidian vault, OS settings, incumbent plugin or previous repository. Preserve the 01A desktop command and protocol. One PR, no new production search UI.

1. **Storage**: compare bounded embedded SQLite layouts (packed float32 BLOB exact scan vs normalized relational coordinates or a simple file-based alternative) on identical small deterministic mathematical vectors, not embeddings or retrieval quality. Exercise scoped filtering and exact rank/tie parity; measure latency and size on a tiny fixture, report limitations. Test FTS5 availability and transaction rollback. Prefer a single SQLite database for manifest/source/lexical/dense records and one atomic visible generation if supported. Implement a narrow transactional foundation with explicit generation/scope/source hashes, strict complete versioned manifest identity (schema, parser/OCR/chunker/serialization/model/tokenizer/backend/profile; no mixing), bounded validated records, rollback, reopen and stale source suppression with caller-provided current source hash. Stage/commit in one transaction; readers see all old or all new, old preserved on injected failure/crash. Derived cache path separate from scoped source files; no source mutation. No actual ML, FTS search quality claim, or production index ingestion. Document actual storage decision in ADR before adoption; prototype code is not a production index.
2. **IPC**: compare current one-shot stdio, bounded persistent stdio and authenticated loopback as a benchmark-only alternative, on identical tiny health messages (bounded count e.g. 20). Loopback experiment only in isolated network namespace / explicitly local scope; no production listener or telemetry. Record timings, process counts, lifecycle/security tradeoffs and chosen production IPC ADR. Implement/test narrow persistent stdio prototype with versioned correlation, byte bounds, malformed/oversize rejection, sequential requests and explicit cancellation/termination/restart; do not mutate v1 synthetic probe or add speculative search APIs. No untrusted arbitrary commands. Use stdlib and share compatible validation logic rather than independent duplicate algorithms when practicable.
3. **Scope**: test a reusable Linux descriptor-relative source-read foundation using trusted root, canonical relative paths, no traversal/absolute/backslash/ignored directory, regular file only, reject symlink ancestors/target, bounded open/read, hash, source freshness. Reject unsupported OS/filesystem explicitly. Scope tests only isolated synthetic directories; no actual arbitrary-vault scan or activation. Discuss limits of filesystem threat model; no false OS sandbox claims.
4. **Resource admission and termination**: design Linux cgroup v2/user-systemd transient service approach. Read actual free memory/disk, require budget/reserves before start, bounded one active job; no privileged or persistent config; fail closed if controller/limits unavailable. Runtime proof on reference host: create uniquely named temporary user unit with MemoryMax <=64 MiB, MemorySwapMax=0, CPUQuota <=25%, TasksMax <=8, KillMode=control-group, RuntimeMaxSec <=15s and TimeoutStopSec <=1s; verify actual cgroup file values, tiny process tree with sleeping descendant, cancel/stop and assert both members are gone, then restart. No stress/OOM tests. Use bounded synthetic helper only. CI deterministic tests for admission, denied conditions, lifecycle/command arguments and all portable parts; actual host proof is explicit separate command, no service changes or dependency on user systemd in GitHub runner. If any required isolation is unavailable, fail closed and report rather than disable protections. No detached work. Include resource pressure/recovery behavior and no automatic workloads in design.
5. **Evidence and decisions**: add reproducible small benchmark(s) and acceptance tests, record actual environment version and measured aggregate results, no private paths/logs. ADR(s) compare options, tradeoffs, chosen storage/IPC and resource/scope controls, exact experiment boundaries, limitations / deferred gates. Update applicable architecture/component docs and link this prompt in roadmap (no duplicate ledger). Validate existing 01A regression and Python tests, CI for exact head, no test weakening. Keep modules narrow and avoid unnecessary new dependencies.

## Acceptance

- V01B-01: measured embedded storage alternatives and FTS5 compatibility, exact score/filter/order parity on synthetic numbers, decision and reproducible command.
- V01B-02: manifest identity strictness and atomic generation across source, lexical and dense records; concurrent reader snapshot, injected failure and actual killed process leaves old generation, reopen; stale/missing hash and incompatible identity reject; source bytes unchanged.
- V01B-03: measured stdio alternatives and bounded persistent protocol; positive and negative correlation/framing/timeout/cancel/restart tests; no default network listener; isolated loopback measurement or explicit blocked reason; ADR.
- V01B-04: bounded scope source access, traversal/symlink/ancestor/nonregular/ignored/oversize rejection and source freshness tests.
- V01B-05: admission before allocation, deny on unavailable controls/insufficient memory/disk/concurrency, actual Linux cgroup v2 limits and process-tree cancellation/restart proof with tiny helper and no orphans; resource host test explicit and reproducible.
- V01B-06: ADRs/traceability, dependency/license checks, full lightweight regression, exact-head hosted CI, fresh independent review with no blockers, merge verification. Phase-close evidence is synthetic foundation only, not MVP or production acceptance.
