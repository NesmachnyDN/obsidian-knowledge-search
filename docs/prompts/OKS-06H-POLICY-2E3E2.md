# POLICY.2e3e.2 — owner-serialized durable live transition admission

Base: `95c09ec7a43a4c93197b84d80c8a81b05cde9e32` (accepted #130). Authority: AGENTS, SECURITY, SDD, SPEC AC-11-POLICY-02/03, ARCHITECTURE, ROADMAP POLICY.2, ADR-0019/0021, POLICY.2e1–2e3e.1, #79/#78/#105. Standard bounded slice. Read governing and path-local instructions before editing.

Integrate `DurableLifecycleLedger.commitLiveTransition` into the existing `NewMaterialTracker` and `NativeLifecycleOwner` without adding a parallel authority. Provide a host-private owner-serialized operation for one authenticated, ordered, file-level event (create/modify/rename/delete) from a future admitted native event boundary. A caller supplies event sequence, path(s), pinned native owner identity and a current-event fence; never caller-supplied descriptor proofs or successor snapshots. The operation must derive the prior from exact live tracker and committed ledger evidence, and fresh proofs from the canonical reader. Require admitted baseline, exact epoch/context and anchor, bounded event and inventory; synchronize reservation and suspend lifecycle authority/exports before any callback/await. Fail closed on overlaps, replay, loss of owner/event/rules/context, unsupported events, ambiguous/tombstoned collisions, stale evidence or inconsistent unrelated files. Preserve the existing pilot API semantics outside durable authority; prevent unguarded mutations of a durable epoch or during its pending transaction. Do not silently downgrade to legacy classification.

Use the existing complete Markdown inventory for a bounded post-event observation. Compare it with the exact predicted successor (all admitted unrelated paths/proofs/owners unchanged; no unexpected paths or missing records; deleted paths absent). Check owner binding, duplicate identities, stable descriptor identity, distinct canonical version for modify/rename (same content permitted), and exact event/sequence. Revalidate complete evidence before CURRENT and again after commit. Reuse ledger delta validation rather than create a separate ledger engine; keep tracker publication atomic and callback-free after final fences and exact committed anchor verification. No authority is active during an operation. Distinguish denied, committed-not-live and uncertain-publication; on any failed or uncertain transition retire and physically drain the owner, never assert rollback or automatically rebaseline. On success retain state/origin/originVersionId, advance sequence exactly once, and allow subsequent proven events. Close/abort/rules change/reentrant callbacks cannot resurrect evidence. A restored partially ambiguous ledger is not sufficient for this exact transition transaction.

The existing real host probe explicitly records event authenticity/completeness as UNPROVEN; callback occurrence or an incremented local counter alone cannot establish that property. Keep production callbacks conservative in this slice unless actual admission evidence exists; no newly enabled production event authority, policy grants, provider, source writes, production Vault or runtime/platform claim. Follow with the real native event admission/evidence slice and all-role policy fences. No unrelated refactor or dependencies.

Acceptance: real isolated Linux ledger/reader and synthetic native owners, success create/modify/rename/delete including unchanged content and provenance; restart/restore, unrelated record invariance; stale/replay/overlap, same-byte replacement, owner mismatch, ambiguous path/collision, missed unrelated change, cancellation before and after CURRENT, reentrant callbacks, retirement and physical lock drain. Test that classification/export is unavailable while publication is pending; verify no bypass via old mutators and no regression of previous pilot/baseline. Tests must use canonical proofs, not injected snapshots for success. Run typecheck, build, targeted tests where feasible; report sandbox UID/flock limitations. Orchestrator will run actual Linux tests, applicable regression, independent exact-HEAD review and merge only after gates. Worker must not commit, push or merge.
