# POLICY.2e3d.2b — tracker-owned durable initial-baseline admission

Base: `e2a204887a75a9d6d64323c58d8965a36cb1631d` (#126). Authority: AGENTS, SECURITY, SDD, SPEC AC-11-POLICY-02/03, ROADMAP POLICY.2, ADR-0019/0021, POLICY.2e, 2e3d.1 and 2e3d.2a, #79 comment 7199148310 and the #126 review recommendation. This is a bounded synthetic prerequisite. It adds no production caller, UI, source write, grant, provider, egress, real Vault access, dependency or normative-scope change.

The existing `NewMaterialTracker` owns the admission orchestration. The durable ledger is evidence storage, never a second lifecycle or policy authority. Consume the exact in-memory preview identity once. Pin root, scope, host/session object identity, rules revision, ordered exact candidate proofs, native owner object identity, lifecycle/event revision, captured cancellation signal and a bounded monotonic expiry. Admit only from a pristine tracker and an empty revision-zero durable epoch; any pending new, ambiguous/deleted/legacy event evidence, concurrent/reentrant action, cancellation, expiry, source/rule/root/session/owner change, failure or uncertainty seals exact lifecycle authority.

Use the canonical complete Markdown inventory and exact native owner lookup for every observation. Compare the full observed set with the preview; never admit a subset or silently omit a source. Initialize an empty durable epoch only under the explicit still-current local confirmation fence. An empty epoch alone never makes an original existing. An interrupted staged initialization without CURRENT remains unavailable under the existing recovery rules; never automatically reset it. Replaying a consumed preview denies without granting new authority. Build immutable baseline records from the first complete observation, invoke `commitInitialBaseline`, and have its revalidation repeat complete proof/owner/current checks after staging. The ledger's synchronous final owner/expiry/retirement fence remains the durable linearization point. Cancellation before it denies; cancellation afterward is a live-authority revocation and cannot pretend the durable commit was undone.

After a committed ledger result, perform another complete proof/owner/current observation. Install live `existing` tracker state only after that succeeds, with no asynchronous boundary before the final current/owner checks and local state installation. A durable commit followed by failed re-observation remains non-live and seals the tracker. Serialize pending admission with retirement and keep the ledger's exclusive physical drain through close. Preserve the accepted pilot and independent Basic Search.

Acceptance: adversarial Linux synthetic tests cover positive immutable exact admission and reopen; complete inventory mismatch/subset denial; preview replay; reentrant/concurrent admission; pending-new, ambiguous and legacy evidence; cancellation before and after durable linearization; expiry; source/rule/root/session/owner changes across awaits; nested proof-version mutation after a passed commit record; staging revalidation; close/retirement physical drain; uncertain publication; and no live state after cancellation. Run focused tests and typecheck. Independent exact-HEAD review and normal SDD gates remain required before any merge.
