# POLICY.2e3d.3a — native owner baseline readiness and local transaction

Base: `1767af4ac53ca64965f5bdcc70870aedc1c6fcd3` (#127). Authority: AGENTS, SECURITY, SDD, SPEC AC-11-POLICY-02/03, ROADMAP POLICY.2, ADR-0019/0021, prior 2E3C/2E3D1/2E3D2A/2E3D2B contracts, #79 comment 7199867120. Bounded owner prerequisite; actual UI command/modal and isolated native host admission acceptance are 3b, not claimed here. No new grants, provider, egress, source writes, production Vault or installed plugin modification.

Reuse the existing NativeLifecycleOwner, tracker, canonical complete Markdown inventory, ledger and exclusive drain. On startup retain optional readiness only for demonstrably fresh storage (null verified committed state) or valid pristine revision-zero uninitialized epoch with a pristine tracker. Never initialize automatically, classify originals, or grant access from readiness. Preserve existing exact restoration of non-pristine committed records (never rebaseline). Distinguish proven corrupted committed bytes/anchor/schema/digest from ambiguous orphaned artifacts, unavailable/unsafe/contended storage and retired owner; ambiguous is not fresh. Preserve the existing generic ledger error code and all security checks. Basic Search remains independent.

Owner reserves preview/admission operations before any host callback. Explicit local preview obtains bounded complete canonical inventory, verifies owner identities, creates the existing tracker-owned immutable one-use preview, and exposes only local count/paths/monotonic expiration and opaque identity. Empty complete inventory may be explicitly admitted; retain old pilot empty rejection. Do not ignore preexisting native/legacy event evidence. The owner binds confirmation to its exact returned preview object, consumes once, uses captured epoch signal and monotonic clock, delegates solely to admitInitialBaseline, never to the legacy immediate confirm path. No new parallel authority or ledger. Keep all source classification unpublished until commit plus fresh proof. Distinguish admitted, denied, committed-not-live and uncertain-publication; invalid/replayed token denies, stale/expired/retired/failed verification has typed local reason without source text. Explicit cancellation, concurrent/reentrant operations, owner/root/rule/session change and retirement fail closed. Close immediately revokes authority, drains startup and the pending owner operation before releasing the physical ledger lock, and remains idempotent. Do not silently retry or reset.

Acceptance: synthetic Linux owner integration tests for fresh and revision-zero readiness, no automatic initialization/classification, corrupt/ambiguous/lock unavailable, exact positive durable admission and reopen, empty complete inventory, one-use token, cancellation/expiry, mismatched source/owner, competing operations, native retirement and physical lock drain during admission. Existing restoration, source event and Basic/Graph regression unchanged. Actual RU/EN native UX and isolated real Obsidian guarded-path tests remain separate prerequisites of full 2e3d acceptance. Follow normal exact-HEAD independent review, CI and postmerge gates.
