## Versioned internal chat contract (v1)

ChatScope is a discriminated union: vault-wide or selected. No optional scope meaning both modes. Selected selector kinds: active note, editor selection, explicit file set, folder, explicitly applied search results, Properties/metadata filter. Store immutable selector snapshot and resolved allowlist (canonical sourceId + SHA-256 and optional exact original source range), predicate snapshot and authority revision; do not trust model-provided paths. Resolve from trusted host current Vault. Folder uses path-segment membership, not string prefix; no recursive unbounded discovery. Applied search results are explicitly snapshotted source identities, not a dynamic replacement query. Properties scope is an explicitly applied typed predicate snapshot resolved within allowed sources. All selections intersect allowed/eligible sources, never confer authorization. Snapshot selected membership; on rename/delete/change/reclassification/filter drift or source invalidation fail closed until user explicitly reapplies scope. Empty selected result is not Vault-wide.

Use canonical request scope IDs and predicates before ranking. Range selections admit only verified original locator spans fully contained in the selected range (see normative mapping below); never disclose text beyond it or fabricate clipped EvidenceHits. If no such hit exists, return insufficient evidence; UI explains range coverage. Unsupported files and unavailable/unverified sources are reported, not silently omitted or treated as notes. First profile supports independently accepted Markdown only. Later Gate C formats need verified native locator support. Vault-wide is an explicit choice (no default automatic egress) over current eligible sources. Re-resolve and recheck exact membership and source versions at retrieval, preview, before dispatch and before publishing/navigating.

### Normative selected-range mapping (B-01)

Capture the exact active Markdown TFile, source ID, host scope revision and editor buffer with one explicit nonempty contiguous selection. Obsidian editor endpoints are zero-based line and UTF-16 code-unit column; order anchor/head lexicographically. Read original bytes through the existing bounded verified source reader, require valid UTF-8 under the canonical parser rules, and prove the complete editor buffer equals the decoded original after only CRLF/lone-CR to LF normalization on both sides. Do not save or modify the note. Reject unsaved divergence, ambiguous/multiple ranges, missing file, out-of-bounds or surrogate-splitting endpoints, unsupported encoding, invalid line mapping or a changed buffer/file/hash/revision during capture. An empty selection is invalid, not the whole file; partial-line and multiline selections are valid. Build a bounded physical-line table from original bytes (same delimiter rules as markdown-parse.ts, including an explicit terminal empty editor line after a final delimiter). A column may equal the line's UTF-16 length, never address delimiter interiors. Convert each endpoint by adding preceding original physical lines with their original delimiters and the selected line prefix, counting UTF-8 bytes and Unicode code points independently; CRLF contributes two bytes and two code points, astral characters one code point and two UTF-16 units. A start at the following line's column zero lies after the preceding original delimiter. Store immutable half-open byte and code-point intervals, source SHA-256, source ID and scope revision. No Unicode normalization, fuzzy matching, clipping or line-number-only authority.

Before candidate ranking/context selection apply the exact source allowlist and range eligibility to canonical candidates using the existing retrieval path; extend its bounded filtering contract if needed, not a second retriever. Every locator of an admitted hit must have matching source version, be nonempty, and lie wholly inside both intervals; verify actual excerpt against original bytes using canonical evidence verification, including any intervening text represented by the excerpt. If containment of the entire excerpt cannot be proved, reject that hit. Repeat before preview, dispatch, publication and navigation; invalidate on editor/source mutation even if path unchanged. No matching full span yields insufficient evidence without I/O to a provider. Test LF/CRLF/lone CR, terminal empty line, emoji/surrogate boundary, combining characters, reversed and multiline selections, unsaved edits, partial-block and empty ranges; assert no out-of-range payload or citation.

ChatTurnRequest v1: session ID, unique turn ID, owner/authority revision, scope snapshot, current user question, explicitly selected prior user questions (optional), generation configuration/credential-binding revision and deadline. All IDs are host-local opaque bounded values. Reject unknown version/fields or stale/replayed owner; never trust caller-supplied authorization. ChatTurnResult v1: matching session/turn/scope/revision, phase, typed error, coverage (eligible/excluded/unsupported/stale/returned counts or explicit unknown), current verified GeneratedEvidenceClaims with canonical EvidenceHits, no raw provider response or secret. States: idle, retrieving, permission-required, generating, complete, insufficient-evidence, cancelled, unavailable, failed. ProviderFailureCode is reused; use a small separate typed scope error for empty/invalid/changed/unsupported scope and explicit busy when authority contention occurs. No automatic retry or fallback to unrestricted, dense, or ungrounded answer.

## Per-turn flow and budgets

1. Resolve visible scope and capture host-owned operation identity. One active turn across chat sessions, one generation operation across search/chat; new chat or scope changes revoke owned operation before observers. Search remains usable; a superseding search may explicitly retire the chat turn, never steal its grant.
2. Search using current question (and explicitly selected bounded prior user question context if applicable) via canonical lexical terms/typed filters. No automatic model query rewrite. Deduplicate by original source/version/locator; deterministic ordering. Show evidence coverage, including top-K truncation as partial, not exhaustive. No evidence => no outbound request.
3. Assemble bounded complete hits in rank order; exclude out-of-scope hits before preview. Do not silently truncate input or change classification. Preview exact composed query, excerpts, endpoint/model, classifications, limits and local/cloud boundary. Confirm once through existing host grant; no credentials or grants in transcript/settings/logs. Existing classification policy permits synthetic/public only; unknown/internal/confidential deny, note text/Properties cannot self-authorize. Require the per-item attestation and host binding defined below before the final preview (no blanket automatic relabeling).
4. Bind exact query/excerpts/source versions, role, provider config, owner, scope snapshot, credential epoch, deadline and single-use preview; revalidate before dispatch and publication. Reuse existing transport/verification and active deadlines. Extend host operation binding, not transport bypass. No streaming partial publication. Render quotations only when parser verifies exact text, label all other claims inference and verify citations resolve to current allowed original hits. A cited inference is not guaranteed true. Empty claims => insufficient evidence. Reject invalid/out-of-range/duplicate citation IDs, tools and malformed/model-mismatched responses.
5. Keep only bounded ephemeral history. Max 4 retained sessions, 12 completed turns/session, 2 prior user questions explicitly selected per next turn, 2048 UTF-8 bytes per question; max 64 KiB retained serialized transcript per session and 256 KiB aggregate, evict entire oldest turns/sessions (never active). Clear incompatible history on authority invalidation; no hidden history transmission, no prior assistant answer as evidence. Existing provider maxCandidates/maxInputBytes/maxOutputTokens/timeout and wire limits apply cumulatively to the full assembled query and passages; reject oversized input and display omitted coverage. Token budget: enforce configured output cap, and before real-provider admission require an accepted tokenizer or conservative proven upper bound for full serialized input including envelope/system/schema, provider context window and cost ceiling; byte caps alone do not establish a token/cost guarantee. No actual paid calls without separate approval. Synthetic fixtures must exercise boundary failure.

### Host-owned credential binding (B-02)

The shared SearchController/host authority issues an in-memory opaque, monotonically increasing generation-role credential epoch (safe integer under a unique host-instance identity; overflow or reload retires the instance). The epoch is not derived from token bytes. On initial transient credential commit, replacement or clearing (even same bytes), resolver completion accepted for a new binding, role/config/endpoint/model change, explicit cancellation/revocation, owner retirement or unload, atomically retire the previous binding and advance the epoch before observers/callbacks. Reject any late resolver result under a retired revision. Never place credentials, token hashes or resolver payloads in a preview, grant, history, diagnostics or settings. Keep the secret only in the existing transient role-specific boundary; clear it on retirement/consumption and do not issue a second storage mechanism. A one-shot credential may be held by the active operation until settlement; consuming a preview retires that preview, not the active operation's credential epoch. After terminal publication or failure retire the consumed binding; ordinary terminal cleanup alone does not invalidate a successfully published transcript. Explicit credential changes or revocation do invalidate affected transcript.

For a chat turn, acquire the transient credential binding before issuing the final consent preview (no provider request). Bind host-instance identity, owner/session/turn, credential epoch, exact configuration digest and immutable scope/classification snapshot to the single-use preview and its host-issued disclosure grant or shared host-owned grant envelope. The current guard verifies binding identity and active ownership before resolving a secret, before every asynchronous boundary and immediately before transport dispatch and terminal publication; the transport receives only the captured token for that exact operation. If the credential input changes, retire the preview/operation, cancel, and require a new preview and approval; never reuse an old confirmation with a new token. A non-cancellable resolver/verifier remains subject to existing bounded retirement/drain rules. No callback can advance/revive authority without a fresh host admission. Test same/different token replacement, clear, resolver late completion, cancel, role/config change and reload; inspect actual outgoing request counts, exact credential binding and absence of stale publication. Preserve existing search clients through the same shared authority, not a parallel grant issuer.

### Trusted per-item classification (B-03)

For the initial loopback profile, only an explicit local user classification attestation through the trusted host confirmation UI is supported; neither notes/Properties, model output, caller-supplied labels nor selection imply classification. Before issuing a final disclosure preview, present a local classification-only draft with the exact current question, each explicitly selected prior question and every verified excerpt separately, initially unclassified (unknown). The user must explicitly attest each item as synthetic or public, or mark it blocked. This is a classification action, not consent. The legacy search-wide assertion remains unchanged only for the already reviewed one-shot search pilot; chat must not inherit or offer a blanket assertion. If any item lacks a current attestation or is internal/confidential/unknown/blocked, fail closed before the final preview and network I/O. Do not let a consent click override any known denied label; existing independently established restrictive classification always wins. Require the user to explicitly revise the local selection/query and reclassify rather than silently drop or relabel items. Keep attestation ephemeral, bound to exact UTF-8 digest, item kind and unique item identity; excerpts additionally bind source ID, SHA-256, locator and excerpt digest, prior questions bind session/turn and current scope. Bind all attestations to host/scope/credential/config revision. Recheck bindings at preview, dispatch and publication; scope/source/classification change or cancel retires them. No standing authorization. Mixed synthetic/public items retain distinct classifications; the serialized composed question receives public if any constituent is public, synthetic only if all are synthetic, with every constituent separately verified before composition. Use the existing per-candidate classification field and shared host-issued disclosure grant; bind the constituent digest/classification list in the host-owned envelope as well as the composed-query digest. No classification labels or source identities need leave the host. Unknown or denied input yields DISCLOSURE_DENIED, zero requests, no final preview. Verify missing, forged, mixed, changed, replayed and cross-session attestations and classification/consent separation in adversarial tests.
