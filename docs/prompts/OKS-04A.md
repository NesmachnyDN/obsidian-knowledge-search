## Slice and acceptance
Implement independently authored TypeScript-native, offline Markdown reader/parser, Unicode lexical index, typed Properties (strict no coercion), wiki-link metadata, canonical source identities/UTF-8 and code-point spans, immutable generation and source-verified EvidenceHit. Use public Obsidian APIs for enumeration/events and desktop Node filesystem only for bounded, uncached secure source bytes and plugin-private generation storage. Version protocol, schema and storage; fail closed on unknown identity. Support fresh-install, startup reconciliation, file creation/change/rename/delete, cancellation, failure rollback, crash/restart, rebuild, quota, resource limits, unload and no stale-source display. Reconcile missed events and rehash candidate source before presenting results. Store only derived files; never write vault Markdown. Write and test a concrete ADR for the storage selection.

Use a capped asynchronous one-file-at-a-time native **browser Web Worker for Markdown parsing**, after verifying actual Obsidian host compatibility; use a single-flight cooperative generation writer. Node worker_threads are explicitly unsupported in tested Obsidian V8 and must not be installed as an external runtime. Measure event-loop delay; do not advertise a hard memory sandbox or system-level worker isolation merely from a renderer Web Worker. No Python process, Docker, model, external network or advanced retrieval in the Standalone core. Existing v1 synthetic probe stays available, unchanged in meaning. Ignore unsupported source types, provide explicit diagnostics; do not traverse wiki graph. UI, search pane, navigation, backend selection and full clean-install acceptance belong to 04B/05.

## Positive/negative and contract gates

Ensure filters and freshness precede Top-K. No report shall claim real Obsidian interaction if only a mock was exercised.
