# OKS-05B — Opt-in Advanced local execution and lifecycle bridge

**SDD:** bounded slice, Draft PR to develop, independently reviewed exact HEAD before conditional squash merge. **Base:** `990d82c11162e88701284b2af8469163480d26f8`. **Dependency:** OKS-05A PR #13 merged, Standalone installation validated. No aggregated-PR exception. Public synthetic data only.

## Authority, capability and architecture

Apply AGENTS, SECURITY, SDD, SPEC, ARCHITECTURE, ROADMAP, DEPENDENCIES, REUSE, portable-model and ADR-0001–0008. CAP-07/AC-07 (observable opt-in settings/status), CAP-08/AC-08 (restart/cancellation and Standalone preservation), CAP-09/AC-09 (resource/lifecycle admission), CAP-10/AC-10 (offline/privacy) are primary; prepare but do not claim CAP-02/04/05. Preserve Standalone API v1, native source/evidence identity, existing provider/retrieval, local generation files and legacy manual synthetic probe.

**Deployment decision:** choose only the **opt-in External Backend local stdio candidate** of ADR-0006 for the already-installed Python reference runtime. Bundled Advanced is **not selected** in 05B: verified BGE-M3 weights alone are 2.27 GB and there is no approved plugin-compatible WASM/runtime, license/distribution closure or verified bundled inference. Document this evaluation in a new decision ADR with versioned protocol and threat model. A trusted operator explicitly configures absolute interpreter and backend entry paths. Use a plugin-owned, bounded, one-child local stdio health/lifecycle channel without shell, TCP listener, dependency download or source-document transfer. The stdio child is an optional separately provisioned runtime; never mandatory for the Standalone installation. Parent-held private pipes provide process-local binding; do not claim unrelated local clients are authenticated. A future listener would require independent authentication/consent design and an ADR.

## Bounded implementation requirements

1. Define a strict, versioned **health-only** cross-language wire envelope for 05B (no source, query, vector or vault path fields), with finite input/output sizes, strict JSON, unique fields, exact nonce/request correlation, explicit capability/readiness semantics and typed error codes. Do not silently reuse the v1 synthetic probe or expand its meaning. Keep 05B protocol separate from the future full canonical EvidenceHit/schema gate.
2. Add a narrow, testable TypeScript advanced transport/controller module with at most one active child and pending request; absolute-trusted-path validation including ownership/link and nonregular-file checks, isolated Python flags, disabled ambient PYTHON* and no shell; closed-by-default output, metadata-only diagnostics, deadline, bounded stderr, no stdout framing ambiguity, bounded cancellation/unload/reload process-tree termination, no orphan. Fail closed on invalid config/protocol, backend failure or lifecycle race. Do not start any heavyweight workload; 05B health worker is lightweight and accesses no Vault files.
3. Settings must be opt-in with explicit enable, selected local-stdio profile and trusted interpreter/entry config, strict migration from settings v2 preserving Standalone fields. Default disabled. Invalid/incompatible settings cannot enable a backend. Safe UI feedback for configuration and connection/disconnection/health, with no secrets/private paths in logs or default diagnostics. Enabling backend must not disable standalone or elevate dense/hybrid readiness.
4. Advanced transport status is separate from search algorithms. All dense/hybrid requests continue to yield truthful `CAPABILITY_UNAVAILABLE` and `executedMode: none`. Local stdio health success is **not** model-backed retrieval readiness, and the absence/crash of backend must leave plugin-native Markdown lexical search operational.
5. Real Obsidian Desktop 1.15.1 synthetic disposable Vault/profile smoke with explicit optional backend opt-in and negative disabled path; no production Vault or real document transfer. Verify no listener or network dependency. Existing package-only clean install must stay unchanged and succeed with no Python available to the installed default profile.
6. Add focused adversarial tests: duplicate JSON keys and unknown versions, hostile oversized frames, malformed/invalid UTF-8, forged correlation, stderr floods, child ignores SIGTERM, crash/EOF, timeout, stop/restart, disabled->enabled->disabled, reload and concurrent requests. No compromised/foreign executable startup from untrusted source input. Host memory and resource preflight before any future heavy jobs, with fail-closed **advanced** state when cgroup control for heavy processing is absent.
