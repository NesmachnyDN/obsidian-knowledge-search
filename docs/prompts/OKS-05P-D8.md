## Scope and public boundary

Keep the existing `plugin.api` v1 envelope, search/status/diagnostics and lexical semantics unchanged. Expose a separate in-process `plugin.denseApi` interface, `apiVersion: 1`, async `request(input: unknown)`, with an independently versioned strict envelope; no listener, CLI subprocess, new runtime or dependency. Document actual Obsidian CLI eval invocation, and the trust limit: arbitrary already-trusted plugin/eval code is not a hostile isolation boundary.

Exact operations:
- `{apiVersion:1,operation:"submit",request:SearchRequestV2,space:EmbeddingSpace}`: only dense/hybrid search with explicit nonempty unique Markdown scope in request.scope; derive selected paths from that single field. Validate using existing parseSearch, pilotConfig and validateEmbeddingSpace; preserve typed predicates, metadata and Top-K. No caller endpoint, credentials, classification, consent, grant, preview, arbitrary mode or host callback. Pin configured local provider digest, space and exact detached request at submission. Return an unpredictable opaque operationId capability only to submitting caller; do not expose it in UI, logs or list APIs.
- `{apiVersion:1,operation:"status",operationId:string}`: own operation metadata only (phase, requested/executed mode, expiry, typed error and per-leg status/counts when known). No query, paths, source hashes, preview, excerpts, Properties, token or vector data.
- `{apiVersion:1,operation:"cancel",operationId:string}`: revoke the exact operation and associated UI preview/navigation; no effect on another owner. Cancel pending/running work via existing controller/host fencing; retain no query or evidence.
- `{apiVersion:1,operation:"result",operationId:string}`: read one detached existing ApiRetrievalResult only on completed, still-current operation. One successful read consumes the result; repeated, foreign, expired or superseded IDs never reveal evidence. Preserve requested/executed modes, typed failures and leg semantics; no silent fallback. Revalidate immediately before return using the authoritative selected-corpus/fresh-source and active-generation mechanisms; no second ranking or source-verification implementation. Reject stale/uncertain results entirely, including missed events, settings/space/index changes and async result-read races.
- Explicit typed unsupported for a well-formed rebuild operation; no machine rebuild, rerank, generation or navigation integration in D8. Other unknown operations, versions, fields or types fail closed. Use a separate versioned ok/error envelope, with stable sanitized error codes (including unsupported version/operation, invalid request, busy, not ready, invalid/expired operation, stale and cancelled); never expose exception messages.

Validate strict nested shapes and existing bounds before cloning: 512 UTF-8 query bytes, 16 KiB aggregate request data, 512 unique scoped paths maximum, 32 predicates, Top-K 1–50, dimension 1–4096, existing 256-vector corpus and transport bounds. Do not stringify unbounded/cyclic untrusted input to enforce limits. Reuse exact selected-corpus validation and configured provider identity; do not infer a space or silently trim input.

## Human approval and lifecycle

One bounded pending/running/completed slot; no unbounded queue or result history. Reject a second machine submit while occupied, and do not supersede a current manual consent or operation implicitly. Manual UI actions may explicitly cancel/supersede pending machine work, with revocation. A machine submit only stages an in-memory request; zero HTTP, no auto-confirm, no token or classification input on the API. A dedicated, clearly labeled review-request action in the production ItemView transfers that exact staged request to the existing DenseUiController owner and D6 ApiDenseHost.prepare path. Reuse D7 preview rendering and one-shot human checkbox/classification/transient token confirmation; UI must distinguish machine-initiated operations, display full exact disclosure, and bind the preview/operation identity without exposing the caller capability. No separate grant issuer or scheduler, no programmatic confirmation exported by the machine API. If provider/config changed, fail rather than adopting new settings. Existing host admission is authoritative.

Use a fixed maximum five-minute lifetime from submit (never extended by preview/retry), one active result-read or operation at a time, revision/owner/host/lifecycle fences before and after awaits, timer cleanup and monotonic revocation. Reuse engine captureDenseCorpus, verified source bytes/locators, D6 active-generation/space checks and host status; if a narrow verification port is necessary, extend existing authority rather than duplicating it. Recheck the entire selected corpus (including non-hit sources) and active index compatibility at result delivery. No evidence after scope/source/settings change, cancel, expiry, view close, supersession, reload, unload, uncertain publication or failed verification. No persisted query, preview, token, operation IDs or results; no new stored index or credential path. Bounded metadata-only diagnostics. Basic lexical and legacy Advanced remain independent of unavailable AI. Explicit limitations: already returned data cannot be revoked, and filesystem changes after final verification cannot be atomically excluded without snapshots/locking.
