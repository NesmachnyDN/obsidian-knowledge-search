B-R2-TERM-02 remediation: controller role-local cancellation and runtime-profile revocation/replacement use the same active context as verification and transport. Publish the pinned terminal reason synchronously, including delayed-timer expiry; repeated cancel must not rewrite a published TIMEOUT. A new preview is a distinct operation and may be cancelled normally. Retire completed operations before notifying listeners; stale operations cannot publish into a newer shared search revision. Keep evidence-only notification and cross-role isolation. Test both roles, pre/post-deadline cancel, profile revocation/replacement, observer-visible state, delayed verification settlement, zero HTTP on denial and fresh-consent recovery.

B-R2-TERM-03 remediation: evidence notifications are synchronous snapshot invalidations, not a per-transition event log. Commit terminal state immediately, preserve the first cancellation/deadline reason and retire the operation before worker completion publication. Reentrant unchanged terminal cleanup does not publish again; standalone explicit cancellation and worker settlement retain their existing observable notifications. Coalesce genuine nested role changes into a bounded synchronous wave (initial pass plus at most two follow-up passes for the two evidence roles), never recursively invoke evidence observers or enqueue an unbounded microtask chain. Shared search revision/lifecycle invalidation supersedes an old wave; disposal stops delivery. Snapshot observers must not depend on receiving every intermediate state or continually initiate new work from a notification; state remains authoritative. Preserve cross-role cleanup, independent dense/D8 and the existing deferred expiry behavior outside a notification. No actual-model admission changes.

B-R2-TERM-04 remediation supersedes only the three-pass delivery mechanism of TERM-03. Notifications are coalesced invalidations, not an event log. A synchronous non-reentrant drain maintains one pending evidence revision and one pending lifecycle snapshot; it drains to quiescence rather than dropping a dirty final snapshot. Shared revision supersedes older deliveries and disposal permits only the final lifecycle invalidation. Host-owned dense/D8 revocation is a separate synchronous authority hook, not a queued or quarantinable observer. Evidence-only changes do not invoke it. Supported observers are synchronous, returning callbacks; finite sequences of up to 15 mutation-causing deliveries per callback per wave converge for every still-subscribed observer. On the 16th mutation-causing delivery, the mutation remains committed and the callback is quarantined by identity across both channels for this controller lifetime. Healthy observers continue to the final snapshot. Exceptions also quarantine only that callback. Metadata-only warnings expose quarantine/rejection without callback identity, error payload, query or consent. At most 32 new registrations (including remove/re-add) are admitted during a wave; subsequent additions are explicitly rejected. With N distinct initial observers and at most 32 additions, mutation-causing deliveries are bounded by 16*(N+32); each drain iteration visits at most 2*(N+32) callbacks. No deferred work is added beyond the existing single coalesced expiry microtask. Arbitrary trusted callback computation or externally scheduled operations are not sandboxed; callbacks outside this contract may be quarantined even if their intended sequence is finite. Recovery uses a new callback identity or a new controller; healthy observers remain usable across waves. Preserve all previously accepted deadline, consent, publication, isolation and fail-closed admission criteria; no actual-model execution.

B-R2-LIFE-05/06 remediation: a synchronous notification is a publication boundary, not a point at which a partly committed operation may resume unconditionally. Replace a role preview and its owned timer in one transition before notification (including clearing prior consent on failure); a subsequently superseded returned preview is not current and must not be rendered as a new confirmation. No orphan timer survives invalidation/disposal. Commit message state before notification, reserve the latest lexical job before publication, dispatch only after notification quiescence and recheck shared revision before returning success. Fence control actions across initial invalidation and subsequent publication; a superseded command cannot operate on a detached engine or overwrite newer state. Old asynchronous navigation failures must not erase a newer search. Disposal is terminal and clears engine ownership before final lifecycle publication. Preserve the existing notification budgets, role isolation, deadline and synthetic-only admission rules. Run unchanged reviewer reproducers plus both-role timer ownership, final snapshot, nested search/control, disposal and stale navigation tests. No change to actual-model admission or acceptance.
