# POLICY.2e3d.1 — bounded complete Markdown inventory observation

Base: a8c193d622db28bd603747ba4814dae5fbe2169f (#123). Authority: AGENTS, SECURITY, SDD, SPEC AC-11-POLICY-02/03, ROADMAP POLICY.2, ADR-0019/0021, POLICY.2e through 2e3c, and #79 comment 7197091370. Standard bounded functional prerequisite. No production baseline admission, ledger writes, source writes, lifecycle transition, provider, egress, grants or change to accepted Basic/Graph scope.

Add an independent bounded filesystem observation to the existing BoundedVaultReader, not a second source authority. Its supported domain is the canonical visible Markdown path domain (validPath); dot-prefixed subtrees, including Obsidian configuration, and regular non-Markdown files are explicitly out of scope and their contents are not read. No attachment eligibility is implied. Deny invalid/undecodable visible Markdown paths, unsafe directories, visible symlinks/special files, hardlinked Markdown, cross-device or repeated directory identity, and any native/descriptor enumeration mismatch. No silent truncation. Preserve the existing list() contract and Basic behavior.

Use Linux no-follow directory descriptors and procfs, streaming directory enumeration with bounded buffering and raw name decoding, existing exact original lifecycle proofs, and bounded repeated observation of path membership, directory/file metadata and exact versions. Resource limits: existing 512 sources and 64 KiB per original; additional pilot observation limits 16 directory levels, 1024 entries per directory, 8192 total entries. Exceeding any bound denies the complete observation; #124 tracks scale redesign. Root replacement, cancellation, detected changes, duplicate/native mismatch or unsupported capability fail closed. No scope or membership may be inferred from an index. Return immutable source proofs only, no owner or grant. This is not an atomic filesystem snapshot: sequential reads cannot establish absence of every external mutation, and the trusted native owner and durable admission/commit fence are still missing. A future host must revalidate exact proofs, scope, owner and events before admission and policy use; the inventory API alone cannot authorize an existing classification.

Acceptance: synthetic Linux directories with real descriptor reads, nested/Unicode paths, normal excluded configuration and attachments, empty and exact complete inventory, omitted/injected/duplicate/invalid native paths, same-byte replacement, membership/version changes, symlink/hardlink, per-file, per-directory, total-entry, depth and source-count overflows, cancellation, root replacement and unchanged Basic list behavior. Typecheck, tests, build, standard SDD independent review and applicable checks. Actual Obsidian host admission is deferred to production integration; no real Vault access or broader support claim. A successful prerequisite does not complete POLICY.2e3d or #79/#105.
