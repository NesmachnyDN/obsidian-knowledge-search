## State and boundaries

Reuse RerankingProvider, ProviderConfig and independent role settings; LoopbackRerankTransport, LoopbackJsonTransport, VerifiedEvidenceOperation, projectDisclosure, EvidenceReranker, SearchController, and native confirmation/view. Existing 05P-B accepts a complete Cohere-compatible /v1/rerank response from an authenticated IPv4 HTTP loopback pilot with exact model@revision served alias, 1–50 candidates, <=65536 input bytes, bounded wire/response, one concurrent operation, 100–30000 ms deadline, finite scores, full unique index permutation, deterministic original-order ties, pre/post freshness and typed errors. The machine v1 search API remains lexical; D8 denseApi explicitly excludes machine rerank/generation. No machine self-authorization. 06UX is presentation, not authorization.

Neither existing synthetic proof nor a configured preference proves real model identity, token counts, effective context, pricing, or B-Rerank. No confirmed authorized endpoints serving both required rerank models were identified during metadata-only inventory; installed embedding models are not rerank substitutes. The current transport rejects cloud. Preserve this boundary unless a separate reviewed, explicitly authorized cloud contract is introduced; a local forwarding proxy is not a privacy bypass.

Basic Search remains autonomous without network, S3, dense index, reranker or generator. Reranking consumes exact lexical EvidenceHits and never owns an index. Changing reranker must not change embedding space, corpus generation or dense CURRENT. No default activation, provider lock-in, source writes, new credential store, or model downloads/heavy inference/cloud calls without separate owner authorization. No main changes.

## Preregistered benchmark design (proposed acceptance margins)

Freeze source bytes, manifests, retrieval version, judgments and evaluator code before model execution. Keep historical corpus/v1 (21 sources, 15 tuning / 16 held-out) unchanged and report it separately as compatibility/pilot; its historical scores are already known. Add a fresh synthetic RU/EN architectural evaluation corpus with 100–150 queries total, target 120 (30 tuning, 90 new held-out), >=15 exact-ID and >=15 negative/ambiguous held-out queries; ensure multilingual paraphrase, mixed RU/EN, requirements/ADR, API, constraints, structured Markdown tables, near distractors, identifier and property intersections. Freeze independent relevance labels 0/1/2 by source path and original line with source digest; reviewer checks judgment/manifest integrity and adequacy before model calls. Never tune against held-out or replace its judgments. If corpus target cannot be met, retain pilot status, no selection claim.

Use actual StandaloneEngine, original physical-line evidence, explicit terms mode, same exact scope/filters and one frozen generation. Obtain one top-50 list per query; require stable top-20 prefix (verify independent limit=20 parity); persist synthetic candidate IDs, source hashes, locators, original ranks and manifest digests. Both rerankers consume identical ordered prefixes for N=20 and N=50; fewer available candidates are reported, no padding or new candidates. Fixed output K=5,10,20 (and 50 for candidate ceiling), primary N=50/K=10; report N=20/K=10 secondary. Use same candidate text bytes, no extra context beyond documented model-native pair template. No dense retrieval, alternate chunking or embeddings. Compare baseline prefix for each N, verify all returned IDs and exact original evidence; for zero candidates record not-executed/no-candidates for both (no request), not a successful model call. If any candidate list violates input limits, record failure rather than truncate or cherry-pick.

Freeze template/instructions, versions and provider limits using tuning only, before held-out run. Use one fixed trial per quality query, two additional warm repetitions for latency and stability on the same inputs; counterbalance model order with seeded deterministic ordering, no hidden retries. Report cold separately, workload throughput (queries/s and candidate pairs/s), p50/p95 end-to-end and API duration (nearest rank), explicit attempted/succeeded/failed/cancelled/no-candidate counts, timeout/rate-limit fraction, per-query original/rerank rank changes, token usage and actual cost where applicable, and whole service-process resource measures locally. Record run/manifest hashes, seed, software/model/tokenizer/template/precision, effective context, bounded request count and aggregate resource evidence; sanitize output, never persist credentials or private host paths. No calls from CI.

Score unique original source spans with existing corpus/v1 metric definitions: fixed K precision denominator, recall over all positive judged spans, nDCG gain 2^grade-1, MRR first positive, exact-ID grade-2 direct hit. Report document metrics separately, candidate recall ceiling, positive macro averages, negatives separately (returned counts, no fabricated evidence; rerank is not abstention). For empty or failed answerable queries use zero end-to-end metrics and separately report coverage and successful paired-only sensitivity; do not discard failures to inflate score. Per-query paired differences, 10000 deterministic bootstrap resamples of answerable query IDs (seed 601), 95% percentile CIs; no claim of general population representativeness. Primary N=50/K=10: mean nDCG improvement >=0.03 and lower CI >0, MRR and Recall@10 mean differences >=-0.02 and lower CI >=-0.05, no exact-ID direct-hit loss versus baseline at K=10, no regression in candidate recall at N. Report N=20 and language/category strata, all metrics, not choose winner using post-hoc subgroup results. If both meet gates, choose only with measured operational trade-off; no winner is legitimate. Proposed operational gates: warm end-to-end p95 <=3s, zero held-out provider failures/timeouts (report absolute counts; no reliability guarantee), no critical privacy/provenance/lifecycle violation; explicit approved cost ceiling before paid run. A slower profile requires a separately reviewed decision before acceptance, not changed thresholds after viewing scores.

SPEC/benchmark policy requires comparable Knowledge AI incumbent evidence for AI adoption, or a separately reviewed maintainer alternative if unavailable. Record this separately; a lexical control is not proof of incumbent non-inferiority. No production adoption or release authorization in this phase.
