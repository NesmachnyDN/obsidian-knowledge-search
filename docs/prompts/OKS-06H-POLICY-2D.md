# OKS-06H-POLICY.2d — exact original version identity

Base: `a3055b72faf3caab141d1e7b53a1bf4874fb1ce2`. #79/#105, ADR-0019, AC-11-POLICY-02. Add a bounded canonical original-version proof for durable lifecycle reconciliation. Use the existing Linux descriptor reader, not cached metadata, index membership or path alone. Bind root, path, raw SHA-256 and exact descriptor version (device/inode, size and nanosecond modification/change/birth times); reject inconsistent final pathname/descriptor, non-regular file, hardlinks, root change and oversized input. No raw filesystem metadata in the exported proof. A proof is evidence of an observed version, not a grant, continuous identity or a trusted creation event. A prior lifecycle record is usable only with separately trusted durable provenance and exact current version equality; changed/missing/untrusted state remains unresolved. No inference from startup inventory. Reuse this reader for ordinary reads without a second body read. Preserve Basic availability and existing strict pilot.

Scope: reader and synthetic tests only. No persistence, baseline admission, writer, provider, external request, production Vault or platform claim. The subsequent ledger must bind creation/baseline admission and explicit trust to this proof and fence events/restarts; it cannot accept arbitrary note-supplied values. Validate exact-version stability across reopen, changed content, same-byte replacement, rename, roots, symlink/hardlink/limits and existing reader regression. Full Node/Python, build/package, licenses/audit, applicable CI and independent exact-HEAD review before merge.
