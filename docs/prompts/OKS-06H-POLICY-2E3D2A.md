# POLICY.2e3d.2a — guarded durable initial baseline publication

Base: 0ccdba28c915e4c98061803f0e2f3ed7e1dcf1c6 (#125). Authority: AGENTS, SECURITY, SDD, SPEC AC-11-POLICY-02/03, ROADMAP POLICY.2, ADR-0019/0021, POLICY.2e/2e2/2e3c/2e3d1 and #79 comment 7197091370. Bounded functional prerequisite; no production caller, native preview/confirmation, source writes, new grants, provider or egress.

Add a dedicated guarded initial-baseline transaction to the existing host-private DurableLifecycleLedger, under its current exclusive lock, CAS and physical drain. Restrict this slice to the demonstrably pristine committed revision-zero empty epoch; other histories deny rather than overwrite existing/verified-new/ambiguous provenance. Capture and validate canonical immutable exact baseline entries (existing, baseline origin, origin version equal to admitted version) and expected digest before any async work. No automatic epoch initialization or rebaseline. Legacy low-level substrate methods remain non-authorizing; production initial baseline must use the dedicated guarded path, not unguarded commit.

Require a trusted host-supplied captured AbortSignal, async revalidation callback and synchronous current-owner/confirmation fence (literal true only). Revalidate after candidate and staged anchor have been persisted, before the final existing directory/root/lock fence. The eventual host must verify complete inventory, exact versions, owner, root, scope, rule epoch, expiry and event/retirement conditions; this slice does not prove or implement those host predicates. Deny when revalidation fails, guard throws, signal is aborted, or close begins before publication. Keep the final synchronous current check, close/abort checks and single descriptor-anchored atomic rename in the same JavaScript turn, without await or asynchronous publication after that check. The trusted callback is synchronous/non-reentrant by contract; still check cancellation/close both before and after its invocation. A synchronous rename is the baseline linearization point; it is not an atomic filesystem snapshot or exclusion of all external OS mutations. Preserve existing snapshot/anchor fsync, readback, cleanup, poisoning, valid-current recovery, and physical close drain. A later cancellation/retirement after linearization does not retroactively revoke a committed provenance record, nor authorize live use; later native integration must independently fence publication of live authority and report committed/uncertain outcomes truthfully. On failure before rename, current anchor remains old and no staged candidate can be promoted on reopen; uncertain recovery remains fail closed under the existing trusted-anchor contract.

Acceptance: real Linux synthetic ledger tests of positive guarded baseline and exact reopen, immutable captures, stale CAS, replay and nonpristine/invalid record denial, revalidation false/throw, pre-aborted and mid-revalidation abort, synchronous owner-fence denial/throw and reentrant cancellation/close, close while revalidation is pending (exclusive lock retained until drain), interruption before rename and recovery of only the previous anchor, and explicit post-linearization cancellation behavior. Existing ledger and Basic/Graph tests unchanged. No production admission claim, no real Vault access. Follow-on host integration must bind the actual owner/preview and provide fresh complete inventory and exact proof checks; preserve prior fail-closed behavior until independently accepted. Standard SDD review/CI and post-merge gates apply.
