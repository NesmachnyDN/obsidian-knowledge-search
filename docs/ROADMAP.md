**2026-11-23 product-owner rebaseline:** [ADR-0015](adr/0015-api-first-ai-optional-dense.md) supersedes the original mandatory offline local dense/hybrid Advanced MVP gate of ADR-0006 and earlier OKS-05 contracts. ## OKS-06B scope and ownership (2026-11-24 product-owner direction)

- **Vault is authoritative; graph is a disposable read projection.** OKS indexes existing source-backed cards and links, not a separate canonical entity/assertion store. Mapping is Vault-configurable and versioned; plain wiki-links are navigation edges, not evidence of a semantic predicate. Unmapped/unknown status must not be labeled confirmed. Only explicitly accepted relationships under the Vault's own governance rules may be presented as confirmed; candidate/rejected/superseded or ambiguous relations cannot enter confirmed-only retrieval.
- **No graph confirmation subsystem in OKS.** New entity/relationship discovery, candidate card creation, deduplication, conflict resolution and expert confirmation belong to the existing Vault/agent curation workflow, not plugin-owned graph administration. Existing accepted cards/relations need no second confirmation. Optional future AI-assisted extraction or dependency/conflict analysis requires a separate maintainer-approved scope and contract; this roadmap does not authorize an extraction service, autonomous source edits, a new ontology or a review UI.
- **Minimal user surface:** existing search UI/API/CLI with an optional related-knowledge expansion setting, truthful confirmed-status filtering where configured, and source-backed relation/path explanations. No separate graph editor, node/edge review dashboard or custom visualization required. A missing/unready graph cannot disable basic search; a requested graph mode must not silently report successful expansion if it did not run.
- **Security and lifecycle:** graph artifacts stay host-private, disposable and rebuildable; never sync/export them by default or disclose unauthorized intermediate nodes, edges, source text or path explanations. Reuse canonical source/evidence verification and existing egress controls. No provider requests for deterministic graph construction/traversal. Do not introduce a second dense space, mandatory AI/runtime or a graph database. Retain the original Gate A/B/C partition, and do not expand the active 05P implementation or claim graph acceptance before independent review and 06B.4 evidence.

## Phase exits

- Foundation (00–01B): design and protocol tested; no unresolved blocker to the next slice.
- Document quality (02): measurable structure and token/provenance metrics, provisional policy; retrieval-quality confirmation in 03B.
- Retrieval (03): accepted ADR-0006, reproducible model-backed offline lexical/dense/hybrid experiment with compatible provenance/index and separate independent review; **not** a claim of standalone plugin feature. If model weights/permission or review are missing, phase exit is blocked.
- MVP (04–05): operational no-extra-dependency Standalone with offline occurrence/Properties/metadata, lifecycle and recovery; **Gate A is mandatory**. Provider-backed AI CAP-04/05 and advanced PDF/DOCX/OCR CAP-02/03 gates are mandatory only for separately claimed capabilities; cloud requires consent/security proof. Original two-gate local/offline AI requirement is superseded by ADR-0015.
- Advanced / adoption (06–08): OKS-06UX is a high-priority post-05E settings usability gate before OKS-07; optional features remain individually benchmarked and independently accepted; rollout requires separate authorization.

**Operator deployment track (outside OKS feature gates):** Cloud.ru Evolution Object Storage S3 is the proposed new-Vault synchronization destination; historical Yandex Cloud Object Storage S3 remains a read-only migration source. No live deployment/cutover without corporate network/data approval, a synthetic multi-device conflict-and-restore exercise, independent backups and separate sync credentials. A different, segregated bucket/credential is required for any later optional portable embedding cache. [ADR-0013](adr/0013-cloudru-s3-vault-sync.md).

No branch, PR, task ID or numeric metric is evidence by itself. Before each next slice reconcile the roadmap with current implementation and review. Production vault indexing must wait for maintainer approval and stability checks.
