# ADR-0024 — Search-first product boundary and minimum necessary complexity

**State:** Proposed for independent DOCS_ONLY acceptance; product-owner direction 2026-11-28. Refines ADR-0023, preserves ADR-0015–0023 and all applicable CAP/AC and security gates. No runtime, release or implementation acceptance.

## Decision

OKS exists to process and search existing knowledge, and to make source-backed evidence available to authorized users and optional AI consumers. The authoritative knowledge base is the Obsidian Vault, not OKS. Knowledge management and search infrastructure are separate responsibilities.

| Principle | Normative consequence |
| --- | --- |
| Read-only First | Read originals, authored Properties and relations. Never create or curate knowledge cards, classify at intake, confirm domain knowledge, maintain an entity catalog/metamodel, or mutate originals. Evaluate search and processing restrictions locally without mandatory source writes or enrollment. |
| Standalone First | Core offline text-occurrence and typed metadata search works with Obsidian and OKS alone, without a producer, external runtime, network, credentials or prescribed Vault structure. Optional profiles never become a core dependency. |
| Search First | Each implementation slice must trace to an observable search, evidence, usability or necessary safety outcome. Prioritize a usable search vertical and independently accepted core over optional sophistication; keep Basic available during AI/profile failure. |
| Document Processing First | Local extraction of supported originals and attachments, canonical content and locators, and content-based retrieval are core product objectives for the document profile. Processing means extraction for search, not authoring or curating knowledge. Deliver format support incrementally and prove each claimed format/platform; no parser dependency for the Markdown-only baseline. |
| API First | Optional embeddings, reranking and generation use independently configured, authorized local or cloud APIs. No mandatory embedded LLM or offline AI; local API offline operation requires proof. One active compatible dense generation, with temporary verified migration staging only. |
| Reuse First | Prefer existing reviewed contracts, libraries and compatible immutable extraction artifacts with verified license, provenance, coverage, scope and bounds. Do not copy entire applications, require a producer or create parallel implementations without measured justification. Standalone extraction remains available for supported formats without external artifacts. |
| One Search Pipeline | One canonical source/version, extraction/chunk/evidence semantics and retrieval/disclosure authority across Basic, document, AI and RAG paths. Profile-specific adapters and independent operation lifetimes are allowed; no duplicate source authority or competing production retrieval engine. Do not remove current coexistence fences until equivalent or stronger safety is independently proven. |
| Derived Data Only | Own only reconstructible search artifacts and necessary private operational state (indexes, extraction caches, chunks, embeddings, manifests, bounded session/evidence state, settings and necessary authority metadata). No competing authoritative knowledge store, business lifecycle or domain catalog. Distinguish derived evidence from original facts. |
| Minimum Necessary Complexity | Use the simplest demonstrably correct design that satisfies actual requirements. Justify each owner, state, transition, queue, registry and cross-profile dependency by a reachable requirement and observable failure/acceptance case. Prefer cohesive boundaries and standard mechanisms. Unify invariants, not unrelated lifetimes. Avoid speculative features, repeated local patches for a systemic defect, and complexity justified only by historical implementation. |

## Guardrails and consequences

- Preserve all applicable security and privacy invariants: hard scope, current-original provenance and ownership, fail-closed admission, independent role authorization, consent and credential lifecycle, revocation, deadline, bounded resources, no hidden fallback, no unauthorized disclosure or source writes. Simplification does not waive them.
- Independent operation lifetimes must not be coupled unnecessarily. Distinguish a source revision, search request, provider authorization and index generation. Do not infer a grant from a passive identity or cancellation constituent. Physical retirement and logical fencing must remain correct and observable.
- Evaluate legacy marking/import/curation/lifecycle dependencies against ADR-0023: retain necessary current-source and derivative safety until replacements pass; do not retain producer workflows merely because implemented. Removal or migration requires its own approved bounded contract and regression evidence.
- Scope and complexity reviews must distinguish required mechanisms, optional profile mechanisms, obsolete dependencies, duplication, and unproven hypotheses. File size and test count are indicators, not proof of defects or grounds to delete tests. Demonstrate reachable behavior, compare alternatives and evaluate total complexity and migration risks.
- Gate A is the minimum product acceptance. Gate B and Gate C remain separately required for claimed AI roles and document formats/platforms. Document extraction is a first-class product goal, but this ADR does not reorder the accepted P0–P3 dependency sequence, change format coverage or authorize new provider/production access. Compare acceleration of document retrieval against Markdown RAG in the audit and obtain a separate maintainer decision before changing priorities.
