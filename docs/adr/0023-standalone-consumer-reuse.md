# ADR-0023 — Standalone knowledge consumption, reuse and unified retrieval

**State:** Proposed for independent DOCS_ONLY acceptance; product-owner direction 2026-11-27. No runtime, provider, format or deployment acceptance. Authority: CAP-01–18, AC-11-POLICY-01–03, AC-18, ADR-0015–0022, #78/#79/#105/#111.

## Context and decision

OKS is a deployable knowledge consumer for arbitrary Obsidian Vaults. The Vault's original files and authored metadata/relations are the sole authoritative knowledge source. A knowledge producer, if present, owns external intake, classification at intake, original preservation, knowledge extraction/curation, entity catalogs, deduplication of knowledge, semantic enrichment, relation confirmation, metamodel and business lifecycle. OKS owns verified read access, extraction for search, chunks, lexical/dense indexes, retrieval, reranking, read-only graph projection, evidence, scoped chat/RAG, derivative freshness and its own search/processing restrictions. No competing knowledge store, catalog, authoring/import workflow or confirmation subsystem. Deduplication of exact search artifacts is not deduplication of authored knowledge.

Standalone First and Reuse First are complementary: (A) Obsidian + OKS with no producer, and (B) co-located independent components with optional compatible reuse. Gate A needs no Python, runtime, network, AI, producer, service or prescribed folder/Property schema. Optional AI roles use independently admitted configurable APIs; optional document runtime supports independently accepted formats without a producer. No mandatory service, shared mutable index, third project or organizational schema. Co-location cannot extend rights or become an availability dependency. Local APIs need separate trust and offline proof; one active compatible dense index per Vault, with atomic staged migration.

The search-first product principles and minimum necessary complexity discipline are refined in [ADR-0024](0024-search-first-minimum-complexity.md), without weakening this ADR's source, policy or acceptance boundaries.

## POLICY.2 replacement and preserved invariants

Prospectively replace intake-time marking as a mandatory consumer workflow with deterministic **read-only effective processing policy** for every current original (manually created, imported, edited or existing at startup). Evaluate current verified Properties, saved settings/rules, folder segments, tags, typed note/file types, proven ownership and independent restrictions. Explicit private and hard restrictions dominate all matches. Distinguish proven absence of a Property from unknown/incomplete evidence. Verified absence can receive an explicitly configured eligibility decision, never automatic egress or an implicit permissive fallback; the safe unconfigured/unknown external decision is deny. Exact external is eligibility only. Missing required facts, ambiguous metadata/ownership, invalid or stale input cannot become permissive. No classification by external AI. Show local preview/reasons; no source writes, lifecycle enrollment, or import provenance prerequisite for ordinary effective evaluation. If a configured rule requires origin evidence and it is not verified, it cannot grant eligibility.

ADR-0019 retains current-original proof, source and all-owner attachment restrictions, trusted-provider admission, independent free-text policy, exact one-shot consent, credential binding, scope fencing, revocation before observers, revalidation at dispatch/publication and async boundaries, no hidden egress/split/fallback, derivative lineage, limits and strict synthetic pilot. ADR-0021 lifecycle identity/ledger was designed for marking; preserve its historical contracts and accepted evidence. Only the mandatory dependency on new/existing classification, baseline confirmation, durable marking ledger, trusted import enrollment and writer is superseded for the prospective read-only policy. Source/version verification, event retirement, restart reconciliation, authenticated persistence where used for authority, and index maintenance remain mandatory. No deleting or bypassing existing runtime safeguards on documentation merge. Assess each implemented lifecycle consumer and prove equivalent or stronger denials before any removal; old unaccepted paths remain fail closed. Optional producer-side writes are outside OKS, not required for #79. No retroactive acceptance or provider permission.

Keep processing eligibility, automatic AI corpus (ADR-0022) and ordinary search scope separate. Configurable hard search exclusions (including explicitly designated control-plane material) exclude ordinary index/retrieval, all AI retrieval/context, and derivative reuse; direct authorized original access is separate. AI-only exclusions need not block Basic Search. No hardcoded private folder names, blanket widening or selection override of hard restrictions. Revalidate exclusion revisions and current owner/source versions on every relevant boundary. Gate A is independent of AI-specific policy but must enforce configured search scope and hard exclusions.

## Extraction reuse boundary

Use one provider-neutral extraction contract (working name DocumentExtractionProvider; align with existing ParsedDocument/ParsedBlock). It accepts a verified local source descriptor/version, requested profile and resource budget and returns canonical source-backed content, native locators where authentic, coverage/provenance and typed ready/partial/unavailable/error. Ordered routes: verified current OKS cache; explicitly enabled compatible immutable external extraction artifact; standalone supported local extractor; typed unavailable/partial. No producer callback or remote parser required. Reuse an existing library/adapter instead of cloning it when rights, integration and quality permit; compare pinned native candidates and synthetic tests under REUSE.md and ADR-0017. Full existing format matrix remains unchanged.

Bind exact original bytes and SHA-256, canonical schema/version, extractor identity/version/options/assets, profile, coverage, native locator authenticity, ownership/scope, policy, resource limits and current source. Hash equality alone is insufficient: authenticate provenance/trust and validate schema, coverage, locators, bounds and current authorization before activation; reject forged/stale/incompatible or uncertain results and surface route/coverage. Treat artifact text as untrusted data; do not treat LLM summaries, inferred relations or normalized approximations as exact originals. OCR is labeled derived evidence. Import of immutable compatible extraction is not permission to transmit or trust a producer's policy. Cache/derived state remains host-private, bounded and independently recoverable; no source mutation. If no compatible artifact exists, independently supported local extraction works without producer. Unsupported format/profile is explicit.

## One search pipeline and transition

Original Source → Verified Extraction → ParsedDocument → Chunk → Lexical/Dense Index → Retrieval → Optional Reranking → EvidenceHit → RAG. Existing Canonical contracts evolve versionedly; one authority for source identity, original-version and ownership proofs, hard scope, processing policy, corpus eligibility, generation and retirement. Graph is a bounded projection of existing authored relations (ADR-0020), not another authority. The current native Markdown Standalone and optional Advanced paths have separate lifecycle/representation boundaries; in the reviewed baseline plugin/src/main.ts attachDenseHost refuses creation and activation when settings.ingestion.enabled. Do not remove this guard alone. First map existing owners, storage barriers, canonical representations and source coverage; then integrate a common verified source/chunk snapshot and compatible generation contract, start with Markdown lexical RAG, add attachment evidence through the same pipeline, and enable coexistence only after atomic activation/retirement, scope/policy, resource, source freshness and failure-path tests. Keep Basic Search responsive; no competing production engine, second active dense space, mislabeled hybrid success or hidden downgrade. Preserve current pilot acceptance boundaries.

## Acceptance and consequences

P0: independent rebaseline, preservation of Gate A, current-source policy and hard scope isolation; P1: shared pipeline and actual independently admitted generation with both scopes, lexical-only RAG sufficient initially, verified citations and insufficiency; P2: dense/hybrid/rerank, graph, corpus and incremental maintenance, quality/scale; P3: extraction cache/format breadth, optional portable artifacts and managed runtime/platform coverage. These are priorities, not waivers: applicable dependencies and Gate A/B/C per role/format/platform remain; #80 is deferred, not interactive RAG dependency. Preserve past measurements; no new support claim based on docs, synthetic-only or another platform.

Verify standalone clean installation without producer/files/runtime, arbitrary Vault layout, manual changes and offline Basic Search; combined scenario with compatible, missing, stale, forged and incompatible artifacts and producer unavailable; equal rights/coverage for same supported source regardless of deployment; no writes to originals, no unapproved egress, no policy bypass via artifact or alternate retrieval path. Test multi-owner restrictions, rule/revocation changes, modified/renamed/deleted sources, restart/unload, source replacement, corrupted derivative state, zero stale evidence, hard control-plane exclusion, one active dense generation. For admitted roles verify actual host/API, RU/EN questions, both chat scopes, multi-turn, source navigation, insufficiency, injection, stale evidence, cancellation, failures, budgets, cost and privacy. Test each format/platform independently. See the [rebaseline execution contract](../prompts/OKS-06-REBASELINE.md) and roadmap. Reject dependency on a knowledge producer, duplicated curation, mandatory intake-time writes, untrusted cache reuse or independent search engines as alternatives.
