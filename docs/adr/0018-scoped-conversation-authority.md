# ADR-0018 — Scoped conversational generation

Status: Proposed for independent DOCS_ONLY review (OKS-06H.1).
Authority: ADR-0015, SPEC AC-11-CHAT-01–04, SECURITY, accepted 05P and 06UX contracts; no new provider or format admission.

## Decision

Use an Obsidian ItemView and a bounded, ephemeral conversation coordinator above the existing lexical retrieval and generation authority. The coordinator owns presentation/session identity only; the host SearchController owns operation admission, source retirement, one-shot disclosure and terminal publication. Extract/reuse a shared host-owned evidence operation port as necessary, rather than instantiate another controller or generator or forge its preview. Search view and chat must not consume or overwrite each other's previews/results; explicit contention is a typed busy outcome. Basic Search remains independent of provider failure. No new store, index, parser, framework, credential store or network listener.

The initial admitted engineering path is the existing revision-pinned loopback JSON adapter, with existing explicit synthetic connection check; a successful fixture does not admit an actual model. Cloud and arbitrary compatible origins stay unavailable until a reviewed adapter and exact endpoint/model/revision, classification, retention, cost and credential policy are accepted. The existing synthetic/public disclosure rule is unchanged. Unknown/internal/confidential content is not relabeled by selection or consent. For chat, the trusted local host UI requires a distinct per-item classification attestation before issuing a final disclosure preview; known restrictive labels cannot be overridden, and the existing search-pilot blanket assertion is not reused for chat. The host issues and retires a non-secret generation credential epoch bound to the exact one-shot preview/grant and operation, with no second credential store. A separate decision and independently reviewed policy are necessary for any wider disclosure. Credentials use the existing transient role-specific input/resolver boundary; any secure persisted reference not already supported remains unavailable, never persisted in plaintext. A connection check is neither runtime admission nor content consent.

Each turn resolves an explicit scope to canonical source identities and versions. Selection is a restriction, not disclosure permission; resolve folders/results into bounded exact IDs, constrain the canonical lexical request before ranking, verify range/filter membership and freshness before disclosure and publication. Editor selections are mapped from zero-based UTF-16 coordinates against the exact version-bound original UTF-8 bytes to half-open byte/code-point intervals, without fuzzy matching or silent expansion; the normative mapping and authority lifecycle are defined in the execution contract. Never substitute an unrestricted request on empty/invalid selection. A change to scope or source eligibility retires the affected turn and invalidates incompatible history. Use current original EvidenceHits only; no source content, metadata or provider output can mint authority. Model output is plain text quotation/inference, not commands, links, HTML, tools or authoritative facts.

History is local memory, isolated per chat; default no disk persistence. Each turn uses an explicit bounded question plus selected prior user questions only if previewed and authorized again as part of the exact query. Prior generated answers are not evidence or provider input; re-retrieve original sources. Scope/provider/credential/classification/consent/source authority changes invalidate incompatible transcript and outstanding callbacks before publication. Follow-ups are not a standing grant. Cancel/new chat/close/unload fence late callbacks under the same host authority used by search. Use the existing deadline, bounded verification drain and retirement mechanisms, including LIFE-01–17 and SYS-01–07.

Alternatives rejected: independent RAG engine or dense store (duplicate authority/index); unrestricted conversational history transmission (unreviewed disclosure); arbitrary OpenAI-compatible/cloud endpoints (unadmitted protocol/identity); persistent history (additional privacy and lifecycle contract). The first implementation is lexical-first; additional accepted retrieval capabilities may enter via canonical evidence without changing scope or egress policy. Details and acceptance in [OKS-06H](../prompts/OKS-06H.md).

## Prospective processing policy refinement

[ADR-0019](0019-note-processing-policy.md) supersedes only repeated manual note-excerpt classification in the future accepted target chat profile. Keep the current synthetic/public profile and B-02/B-03/history evidence intact. Use verified original note Properties and admitted provider trust, explicit free-text handling, exact one-shot consent, inherited derivative restrictions and the same host-owned scope/credential/retirement boundary. Do not claim target chat readiness or wider disclosure before POLICY.1–3 and applicable host/provider gates.
