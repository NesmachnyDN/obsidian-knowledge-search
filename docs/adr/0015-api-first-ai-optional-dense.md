# ADR-0015 — API-first optional AI retrieval with autonomous basic search

**Decision:** Product-owner direction accepted on 2026-11-23; repository SDD review and merge pending.
**Scope:** Target OKS architecture and prospective acceptance criteria. No authorization to change a real Vault, contact AI APIs, provision credentials, or install models.

## Context and supersession

ADR-0001 and accepted ADR-0006 established local-first Standalone, but ADR-0006 and the original OKS-05 plan also made an *offline local model-backed* dense/hybrid profile a mandatory MVP-wide release gate. The product owner has explicitly removed that requirement: without Internet, text-occurrence and Obsidian Properties/metadata search suffice, and AI search shall use a configured API, which may be local or cloud-hosted.

This ADR **supersedes only the mandatory offline Advanced AI gate, the local-only External Backend restriction, and the presumption of a required locally hosted model** in ADR-0001/0006, SPEC, ARCHITECTURE and ROADMAP. It does **not** supersede Standalone availability, verifiable evidence, source freshness, typed metadata, privacy, explicit status, resource admission, or the validity of historical experiment results. Do not retroactively rewrite reviewed PRs, benchmark results, or old execution contracts.

## Decisions

1. **Autonomous minimum:** Obsidian and OKS alone support offline search for text occurrences and typed Properties/metadata (including supported tags and link metadata), with deterministic scope, navigation, source freshness and lifecycle. No LLM, embedding service, vector store, Python, model weights, local AI server, or network is a baseline prerequisite. Existing lexical scoring may remain; validate literal occurrence/exact-phrase semantics separately rather than asserting that token search implements substring matching.
2. **Optional AI path:** Dense semantic retrieval, hybrid fusion, reranking and LLM/RAG are modular capabilities enabled only through explicitly configured API providers. A local API can work offline only if the selected endpoint, weights and execution environment are independently verified without Internet; a cloud API requires connectivity. Do not require a heavyweight local model to ship or use basic search.
3. **Independent roles:** Embedding, reranking and LLM/generation providers are independently selectable; none implies that the others are installed or available. Rerank uses selected candidate text, not a persistent embedding index. Generation is optional and never a source of authoritative evidence.
4. **One active dense space:** At most **one active dense index** for one chosen embedding model+revision+serialization/configuration per Vault/profile. Store derived vectors locally outside the Vault in a versioned recoverable generation. During model migration a temporary staging index may coexist; validate identity, dimensions, normalization, query/document instructions and source freshness, atomically activate it, then retire the prior index. No permanently retained index per candidate model.
5. **Separate always-available lexical data:** Typed Properties and lexical search remain useful and accessible when AI is disabled, offline, unreachable, rate-limited, misconfigured, incompatible or being rebuilt. Source events can enqueue bounded pending AI indexing for explicit retry; queue metadata must not leak content. Search requests must never silently claim dense/hybrid execution when a required AI API/index leg is absent. A user can explicitly issue a new basic-search request or opt into an accurately labeled basic-only fallback.
6. **Privacy and egress:** All cloud providers are disabled by default. External processing of a query, document fragment, candidate passage or context requires a documented per-Vault/per-source authorization policy, data classification/deny rules, endpoint allowlisting, authentication, TLS and minimal disclosure; unresolved classifications fail closed. Never export whole Vaults, credentials or production data by default. Apply the same trust boundaries to local network APIs; do not assume loopback/local equals trustworthy. RAG responses must cite exact source-backed EvidenceHits.
7. **Provider-agnostic compatibility:** Versioned API adapters normalize limits/capabilities/errors and preserve the canonical Source/Chunk/Evidence contracts; no API vendor's document/response schema becomes OKS authority. Pin or record model/API versions. Control retry/backoff, token budget, cost/billing guardrails, concurrency, cancellation, rate limits and failure diagnostics, without exposing secrets in logs.
8. **Acceptance partition:** Mandatory Gate A requires only the baseline portion of CAP-07 alongside autonomous offline occurrence/Properties search, source integrity and resource/security gates; it never requires configured AI providers. Optional Gate B is additive and **per claimed role**: B-Dense (CAP-04 real provider embeddings, compatible index and failure/migration checks); B-Hybrid (B-Dense plus CAP-05 true two-leg RRF); B-Rerank (applicable CAP-11 real API over authorized lexical or AI candidates, without an index of its own); B-Generation (applicable CAP-11 real API with original EvidenceHit citations, optionally using lexical-only retrieval). Provider authorization, failure, privacy and resource checks apply to each enabled role. Claiming one role does not force unrelated AI services, dense/hybrid or LLM. Conditional Gate C validates each claimed PDF/DOCX/OCR format independently of AI. The [SPEC gate matrix](../SPEC.md) controls precise applicability. Local offline dense/hybrid is **not** an MVP gate; a release claiming optional features must prove each one separately.

## Model selection and evaluation

- Embedding candidates: BGE-M3 (existing experimental baseline), Qwen3-Embedding-0.6B; availability and exact model IDs must be rechecked at the selected provider before implementation.
- Reranking candidates: Qwen3-Reranker-0.6B (preferred evaluation starting point) and BGE-Reranker-v2-M3. There is **no approved production winner**. Different embedding/reranking model families may be combined; benchmark the joint pipeline.
- Compare at least relevant Russian and mixed RU/EN technical documentation, API identifiers, configuration/code and long documents using a fixed labeled corpus. Evaluate independent retrieval legs and end-to-end quality, latency, cost and source/provenance error rates. Never present cross-provider marketing metrics or mutable prices as verified OKS results.
- See [provider evaluation plan](../AI-PROVIDER-EVALUATION.md) for mutable catalog references and acceptance methodology.

## Consequences and transition

The pre-existing OKS-05D local BGE-M3 implementation attempt is **in flight on another worktree** and must not be overwritten or mislabeled as required target architecture. Its code/tests and host resource experiments can remain useful as an optional local API-backed candidate after explicit re-scoping; the older local-offline execution prompt remains historical evidence, not a release requirement. Reconcile active 05D PR/contracts against this ADR before accepting or merging functionality that claims MVP compliance.

A separate scoped SDD implementation slice must establish provider contracts/configuration/secret storage/permissions, API-backed indexing and optional rerank/generation. Independent review remains mandatory. This ADR records the owner's direction; it does not claim implementation, endpoint readiness, vendor privacy compliance or measured quality.
