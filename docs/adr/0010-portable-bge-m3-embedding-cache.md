# ADR-0010 — Portable BGE-M3 Embedding Cache & Multi-Device Index Synchronization

**Status:** Proposed (maintainer architecture direction, 2026-11-23; independent SDD review and merge pending).
**Scope:** optional post-Gate-A capability; no requirement for autonomous Gate A or for any unclaimed AI role. [ADR-0015](0015-api-first-ai-optional-dense.md) controls AI provider selection and conditional acceptance.
**Related:** ADR-0003 (SQLite experiment), ADR-0006 (execution profiles), ADR-0008 (host-private Standalone), `contracts/portable-model.md` (source/evidence identity).

## Context and objectives

A new Obsidian Vault is being populated incrementally from a legacy **Yandex Cloud Object Storage S3** bucket (~1.5 GiB historical corpus). Multi-device sync to Yandex stopped working on the corporate workstation after network access restrictions. The selected new deployment is **Cloud.ru Evolution Object Storage S3** for the new Vault and a separately permissioned S3 embedding cache (ADR-0013). Vault synchronization is a separate operator-managed Obsidian concern, not a required OKS runtime. Recalculating identical BGE-M3 document embeddings at each host wastes time and compute. ADR-0008 deliberately binds the existing Standalone local index to a real filesystem root path, device and inode. A copied index is **not** a valid portable index. A SQLite database and its WAL/SHM sidecars must not be treated as a multi-machine writable database through file synchronization.

Only when an authorized dense role is enabled, the optional outcome is **portable reuse of computed document vectors**, while each computer retains an independent, transactional, local search index. The source Vault remains authoritative for content, identity, access and evidence freshness.

## Decision

1. **Embedding model (pilot-specific):** pinned `BAAI/bge-m3` with **1024-dimensional L2-normalized** vectors is the first portable-cache compatibility candidate, not a mandatory product embedding model. `engine/embedding-artifacts.json` supplies a pinned reference revision; it does not authorize automatic model downloads or weight redistribution. Freeze the exact model weights/tokenizer revision and digests, input serialization and contextual prefixes, dimension, normalization, numeric encoding and verified inference compatibility in a versioned `embeddingSpaceId`. Same name/dimension across different runtimes/providers is not sufficient without measured output parity. Sparse and multi-vector BGE-M3 are deferred.
2. **Local persistence:** preserve the plugin-native Standalone lexical index and no-extra-dependency default. Optional Advanced uses host-private, versioned, transactional embedded storage outside the Vault. SQLite is the preferred metadata/persistence candidate; `sqlite-vec` is an **unconfirmed candidate** for vector search, subject to benchmark against exact search and embedded ANN alternatives. No mandatory external database/server/Docker. Neither local BGE-M3 nor cloud inference is required for mandatory Gate A. Optional embedding computation is supplied by the independently selected, locally or cloud hosted API provider under ADR-0015; a one-shot local runtime is an experimental alternative, not an API.
3. **Portable artifacts:** export/import immutable, content-addressed vector objects and complete immutable generation manifests, independent of a host's SQLite/ANN files, local paths and local `CURRENT`/rollback pointers. Select a private **Cloud.ru S3 bucket** using provider-neutral S3 semantics as the first optional immutable-artifact transport, separate from the source-Vault synchronization bucket. Publish immutable content-addressed objects before a complete generation manifest; incomplete S3 uploads cannot become active indexes. A synced-directory adapter remains a later alternative. No S3 API/key/bucket dependency is added to Standalone or local/offline Advanced.
4. **Security:** export and import are **disabled by default** and opt-in per trusted folder/collection. Do not include source text, source excerpts, original documents, credentials or absolute host paths by default. Embeddings and their hashes can leak source information and must be classified as derived confidential data. For restricted Vaults, require a separately designed and independently reviewed authenticated encryption/key/revocation scheme before enabling cloud sync. Digest integrity is not the same as publisher authenticity.
5. **Publisher model:** first delivery supports exactly **one publisher** of completed immutable generations and multiple read-only consumers. Multi-writer conflict resolution, cross-Vault sharing, object garbage collection and automatic revocation propagation are deferred. Never delete shared artifacts simply because one device no longer references them.
6. **No repeat document inference:** consumers import verified, compatible document embeddings into their own local vector structures **without calculating document embeddings again**. Changed effective inputs, absent artifacts or incompatible profiles require new embeddings or explicit degraded/unavailable status. Each **new dense query still requires a compatible query encoder**, local or through separately authorized inference.

## Separation from extraction caching and provider policy

ADR-0011 selects **local-only Docling/OCR** and a private extraction cache that retains ParsedDocument text/locators; those parsed artifacts are never part of the portable vector-only sync format. A compatible parsed-document cache survives downstream chunk/embedding/index changes; the separately keyed BGE-M3 vector cache survives local ANN/SQLite index rebuilds. ADR-0012 selects **optional** Cloud.ru BGE-M3 text embedding computation only with explicit user scope consent, local indexing, spending limits and a **separate cloud embedding space** until exact model-output parity is proven. No Cloud Docling or remote source-file upload is implied by S3 vector sharing; source-Vault sync itself is an independently authorized, separately credentialed S3 workflow under [ADR-0013](0013-cloudru-s3-vault-sync.md).

## Identities, keys and compatibility

- `LocalVaultId`: host-private trusted root fingerprint per ADR-0008, retaining file path/device/inode boundary and local scope enforcement.
- `PortableVaultId`: explicit stable identifier for the logical synchronized collection, never accepted as proof of local source equivalence or permission.
- `embeddingInputDigest`: SHA-256 over the **exact UTF-8 input** given to BGE-M3, including heading/context serialization. Compute only after the canonical chunk pipeline has produced the actual model input.
- `cacheKey`: domain-separated SHA-256 over a canonical length-delimited tuple `(artifactFormatVersion, embeddingSpaceId, embeddingInputDigest)`. Source-bound `ChunkId` and original `SourceLocator` are separate and cannot be replaced by the cache key. Identical inputs can reuse the same vector after file rename, but source identity and anchors must be rebuilt and verified locally.
- Verify vectors by strict schema/version, cache key, embedding space, type/length/dimension, finite values, L2 norm and SHA-256 integrity; enforce bounds before allocation and reject unknown or incompatible encoding. Provider/runtime parity requires test vectors and agreed tolerances before mixing embeddings.
- Import binds cached vectors to **locally** verified source hashes, scope, chunk input and provenance; user-visible `EvidenceHit` still needs current original evidence and location. Deleted, modified, renamed, inaccessible or excluded sources cannot produce stale results. A hybrid response requires independently ready, fresh lexical and dense legs and deterministic RRF.
- Local index publication occurs only after all referenced immutable objects in a complete generation are available and validated; atomic local commit with rollback. Out-of-order, conflicting, missing or truncated cloud-sync files must never activate partial generations. Cloud timestamps and sync status are not transactional commit evidence.

## Cross-bucket consistency and deferred activation (maintainer direction, 2026-11-24)

The source-Vault sync and portable-cache transports are independent, asynchronously delivered channels. A publisher may export a complete cache generation while its source files are not yet uploaded to the source bucket; a consumer may receive either channel first or never receive one. The selected model is eventual consistency **conditional on delivery and reconciliation**, with strict local validation before activation, not a distributed transaction or a guarantee of convergence across independently edited replicas. Neither source-bucket timestamps, ETags, sync-client status nor the mere existence of a cache manifest proves local content readiness. OKS does not control the external sync client or require source-bucket credentials.

- **Content manifest:** each immutable generation manifest authenticates a versioned, deterministic content manifest covering the declared export collection/scope, including the collection identity, source identity and raw-byte SHA-256 of each source version, extraction/chunk/serialization profile identity and expected chunk-to-cache-key bindings. Record explicit zero-chunk and non-indexable outcomes, never silently omit sources. Bind the content manifest digest, expected object set and embedding space to the authenticated generation. A separate source-bucket manifest or write is not required. Canonical relative paths may be used only where specifically authorized; otherwise use privacy-reviewed opaque source references with unambiguous local resolution. Source names, hashes, chunk identities and vectors are sensitive; never export source text, credentials or absolute host paths in this format. Metadata and vectors require explicit classification/egress approval and authenticated encryption wherever policy requires it; otherwise deny the export. Freeze schema, canonical encoding, authentication, freshness/replay protection and resource bounds in the reviewed implementation contract.
- **Publisher:** derive the manifest and vectors from the same verified local source snapshot; detect changes during staging and abort or rebuild rather than publish a mixed snapshot. Upload immutable vector objects and content manifest before publishing the authenticated generation manifest as the completion marker. This is a cache commit only, not evidence that content was synced. The publisher remains single-writer; consumers cannot modify shared objects.
- **Consumer:** authenticate the publisher and validate the entire manifest/object set, then reconcile the declared collection against the current authorized local Vault, including coverage, raw bytes, source identity, extraction/chunk inputs and evidence locators. Do not equate the portable collection identity with a trusted local root or infer completeness from an empty or partial manifest. Local-only additions/divergent edits within the target scope must be explicitly reconciled, not silently dropped. Outside-scope files must not block an otherwise complete scoped import. Never write, delete, restore or fetch source documents as part of cache import.
- **Deferred activation:** distinguish waiting for artifact delivery (`PENDING_ARTIFACTS`), verified cache metadata waiting for missing/mismatched local content (`PENDING_CONTENT`), incompatible space, untrusted/corrupt artifacts, denied scope, and a complete locally reconciled candidate. Waiting is not a successful import or an AI-ready state. Stage only authorized bounded disposable artifacts outside active indexes; reject invalid/untrusted payloads rather than retrying as missing content. Report aggregate missing/mismatched counts without private metadata. A generation with unresolved required content cannot be activated, even if every vector object exists.
- **Event-driven reconciliation:** re-evaluate pending candidates on source create/modify/rename/delete, scope/profile changes, startup/missed-event reconciliation and explicit retry, with bounded coalescing/backoff, cancellation, storage/time limits and resumable or restartable staging. A permanently divergent or excluded source must not wait forever: expose an explicit non-ready outcome and a user-controlled abandon/reconcile or local rebuild path. Never fetch source bytes from the cache or overwrite local edits to force a match.
- **Cost protection:** while an explicitly enabled portable import is awaiting a matching generation or content, pending synchronization alone must not trigger document embedding inference, paid retries or automatic provider/model changes. This restriction does not change ordinary explicitly authorized local indexing when portable import is disabled or abandoned. Once the exact local input matches a verified compatible artifact, reuse without document inference. A missing/incompatible artifact or intentional local divergence may require an explicitly authorized local rebuild or embedding calculation under ADR-0015 consent and budget rules. Query embedding remains a separate configured role.
- **Atomic local activation:** before commit, revalidate snapshot identity, current source coverage/locators, local authorization, selected embedding space, and source-event epoch (or equivalent existing lifecycle fence). Abort/reconcile on concurrent mutation; atomically publish only a complete locally verified generation, idempotently and with crash recovery. Reject stale/replayed generations as new activations; explicit rollback is permitted only after fresh local validation. Retain at most one active dense index; temporary staging is bounded and disposable. A previous generation may remain active only while valid for the current requested scope, model and local source snapshot; otherwise dense/hybrid is explicitly non-ready. Regardless of readiness, revoke in-flight stale results and suppress stale/removed/renamed/denied evidence, including after rollback. Basic occurrence/Properties search remains independent and available.
- **Observability:** distinguish artifact delivery from content reconciliation and local index readiness. Expose aggregate counts (expected/verified/missing/mismatched/denied sources, missing/invalid objects), pending reason, retry/cancel availability, last successful reconciliation and active-generation readiness through existing status/diagnostics, without source names, paths, hashes, vectors, tokens or payloads in exported diagnostics. Do not report the external sync client's status as verified by OKS.

The exact state machine, manifest schema, authenticated encoding and local publication boundary require an independently reviewed execution contract before implementation. The acceptance obligations are specified in [OKS-06C](../prompts/OKS-06C.md). There is no cross-bucket lock, coordinated transaction, source-bucket read requirement or new mandatory dependency for Gate A.

## Deployment

```text
Host A: authoritative synced Vault -> local extraction/chunking -> BGE-M3
        -> private local vector index -> opt-in export immutable embeddings/manifest
                                |
                 private Cloud.ru S3 embedding-cache bucket
                      (transport; not the working DB)
                                |
Host B: authoritative synced Vault -> local file/hash/chunk validation
        -> import compatible embeddings -> private local vector index
        -> compatible query encoder + lexical + RRF -> verified source evidence
```

Never synchronize a live SQLite database, WAL/SHM, active locks or host-private generation pointers. The Standalone lexical profile works offline and with sync disabled; requested dense/hybrid mode cannot silently downgrade on incomplete imports.

## Alternatives

| Alternative | Decision |
|---|---|
| Share live SQLite over sync folder | Rejected: concurrent writes, sidecar ordering, partial delivery and host-root binding. |
| Recompute all embeddings per computer | Rejected as default when exact inputs and profiles can be verified. |
| Always-on centralized Qdrant/pgvector or GPU service | Deferred: unnecessary infrastructure and privacy/availability costs for local-first use. |
| Portable native ANN index as authoritative artifact | Deferred until platform/backend portability evidence. |
| Immutable reusable vectors with local transactional indexes | **Selected** as target architecture. |

## Delivery and acceptance gates

**OKS-05C:** preserve the canonical source/chunk/evidence contract and deterministic encoding; do not expand scope to cloud transport.

**OKS-05D:** existing local/offline BGE-M3 source-aware index is an optional experiment; its acceptance is separate from Gate A and does not create an API-provider contract. Production-scale SQLite/vector candidate benchmarks remain a future independent measurement, not a verified result.

**OKS-06C (after independent Gate A acceptance in OKS-05E and conditional OKS-05P if API dense is used):** separate bounded implementation of portable artifact format, opt-in Cloud.ru S3 (provider-neutral) export with objects-before-manifest commit, single-writer/multi-consumer import, synthetic host-to-host acceptance, recovery, data-leakage assessment and explicit user-facing diagnostics. No personal Vault scan, cloud upload, automatic model use or deployment is authorized by this document.

Acceptance scenarios (including the mandatory cross-channel delivery and recovery matrix in [OKS-06C](../prompts/OKS-06C.md)): identical compatible inputs imported across distinct local roots without model execution; model/tokenizer/input/prefix/revision changes invalidate reuse; rename/delete/scope changes suppress stale evidence; partial, reordered, corrupted and malicious artifact delivery fails closed with rollback; offline/absent S3 endpoint does not break Standalone; query encoder availability is explicit; no text/credentials export by default; measurable initial/incremental transfer, disk, RSS, latency, vector precision and retrieval-quality regression. Multi-writer and encrypted sensitive-content mode require later separate gates.

## Consequences

Cache artifacts are disposable derived data, never authoritative source/evidence. Benchmarked vector-backend selection, encryption/authenticity, owner-controlled retention, cross-runtime vector parity and multi-writer protocol remain open. No runtime/code change or cloud setup is implied by this proposed ADR; independent review and merge are required before repository acceptance.
