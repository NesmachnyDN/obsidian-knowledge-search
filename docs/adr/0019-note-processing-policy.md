# ADR-0019 — Note processing policy and provider trust boundary

**State:** Proposed; maintainer direction 2026-11-26 (#78, #79, merged roadmap #81). Acceptance of this DOCS_ONLY decision defines a prospective target, not runtime admission. The strict synthetic/public pilot remains authoritative until each affected role/profile passes its implementation and acceptance gates. History candidate #77 is integrated at `f45ee9da6f689d97b517775fee49fff1e31a4f65` under the previous contract; preserve its evidence and constraints.

**Prospective supersession notice (ADR-0023):** intake-time marking and its enrollment/ledger/writer prerequisites are replaced for read-only effective policy. The table below records the prior target; verified absence is eligible only with an explicit configured decision, unknown/incomplete evidence is denied. Current-source proofs, all-owner restrictions, exact consent, provider admission and role fences are preserved. No runtime change or new permission until implementation acceptance.

## Decision

Use one host-owned policy for processing eligibility, not RBAC/ACL, a second search engine, credential store, grant issuer, index or transport. The canonical note Property is `llm_processing` (case-sensitive key and exact scalar string values). This decision supersedes only the prospective repeated manual per-excerpt classification requirement of ADR-0018 and the corresponding prospective classification interpretation of ADR-0015/05P; scope, source freshness, provider admission, credential binding, one-shot exact consent, budgets, confidentiality and all historical pilot contracts remain intact.

| Verified current original metadata | External eligibility | Trusted internal eligibility |
| --- | --- | --- |
| Property absent after successful complete evaluation | Eligible | Eligible |
| Exact scalar string `external` | Eligible | Eligible |
| Exact scalar string `private` | Denied | Eligible |
| Other value, null, list, number, case/whitespace variant | Denied | Eligible if original and scope are verified and no separate restriction denies internal processing |
| Duplicate/ambiguous key, invalid YAML, incomplete read/evaluation, stale source | Denied | Denied until identity and policy inputs are resolved, or independently verified safe internal processing is separately specified |

Eligibility is not authorization. A restrictive organizational/Vault rule, scope or source denial wins over every permissive default; a restriction may prohibit internal as well as external processing. Missing Property is distinct from missing evidence that the Property is absent. Read original bytes through the canonical verified source path and trusted local parser, not a stale metadata cache, user-supplied classification, excerpt, provider output or inferred label. Reject conflicting parser interpretations and duplicate keys; unsupported formats are not automatically eligible. Preserve offline Basic Search without an AI provider or any note rewrite.

Provider trust is an explicit, independently admitted non-secret profile bound to the exact adapter, endpoint, role, model/revision, configuration, organization/ownership, data routing/retention/isolation and applicable transport security. IP, loopback, local URL, credential presence and UI selection are not proof of internal trust. Unknown/unadmitted profile is unavailable for content. External egress remains disabled by default. A real provider requires separate approval, operational acceptance and resource/cost evidence; the historical synthetic loopback profile does not acquire wider rights by this ADR.

The shared host resolves every source/version and policy decision locally, before final disclosure preview, and binds the exact resolved policy revision, source/attachment provenance, ordered constituent digests, scope, provider trust/configuration, role, owner/host/turn, credential epoch, exact payload and deadline to the existing one-shot consent/grant envelope. Invalidate before observers on policy/source/metadata/ownership/provider/scope/credential change; recheck before dispatch and terminal publication, including every asynchronous boundary. Reject stale, replayed or foreign consent; never substitute an endpoint, split, omit denied items or widen scope silently. No external input classification call. Private or mixed context requires an explicitly chosen admitted trusted internal provider, or a typed unavailable/denied result with an option to explicitly narrow and reapply scope. No automatic fallback. All derivative artifacts (chunks, embeddings, rerank inputs/results, summaries, history, composed prompts) retain the most restrictive constituent authorization and source provenance; unknown lineage cannot be exported externally. Re-evaluate permissions before reuse, invalidate affected derivatives and keep one compatible active dense generation; do not mix incompatible spaces. Do not transmit policy labels, source paths, secrets or unnecessary provenance to providers.

Free-text current and explicitly selected prior user questions are not notes and never inherit note eligibility. Preserve explicit trusted local per-item attestation (synthetic/public or restrictive) for external free text, bound to exact bytes, session/turn, credential/config/policy and scope. Unknown or denied free text cannot be sent externally. For admitted trusted internal processing, use a separate explicitly selected internal profile and exact consent, with restrictive organizational/user policies respected; uncertainty about such restrictions denies processing. Prior answers are never evidence or implicit input. Do not auto-classify a question from its retrieved sources. The target UX eliminates repetitive manual note-excerpt attestation only after shared enforcement is accepted, retains visible effective decisions/reasons and the exact one-shot preview.

## New material marking and provenance

Default action is leave absent; native RU/EN settings may select set external or set private and ordered rules on folder segments, trusted import channel, note type/template, tags and typed Properties. Evaluate deterministic local rules before first external processing: restrictive matches and explicit private win, regardless of order; order only resolves compatible nonrestrictive actions. Missing/ambiguous required rule inputs or failure are not a successful absent result. Expose dry-run/decision reasons; no remote classification, no implicit write, no mass rewrite. Separately enable idempotent bounded writes only for new materials under the Vault's own AGENTS/metamodel, version-check before committing; re-read and re-evaluate the resulting original version before eligibility. Record local rule revision, decision and trusted source/import provenance without private diagnostics. Existing materials remain unchanged; migration/reclassification requires separate authorization. Explicit private is never silently downgraded. Unknown imported metadata is not a trusted channel assertion.

Attachments and derivatives inherit the most restrictive effective decision of all verified owning cards, plus any independent restrictions. Ambiguous/missing ownership or unsupported extraction/metadata prevents external eligibility; no scope expansion through links. Bind ownership identities and versions and revalidate on attachment/card change, rename/delete or reassignment. A restrictive owner's decision cannot be bypassed by selecting the attachment directly. Internal processing requires verified source/scope and all applicable restrictions. No new attachment format claim.

## Alternatives and consequences

Rejected: repeated blanket approval of arbitrary note excerpts as public; trusting IP or Property alone as authorization; a second access-control subsystem; automatic external-to-internal fallback, mixed interactive request splitting, persistent unrestricted history, or multiple dense indexes. The deferred external-first/internal-remainder batch idea (#80) requires separate design, provider admission, idempotency and budget/space compatibility; it is not a chat dependency.

This target expands possible eligibility but not existing egress permissions. The current pilot remains synthetic/public-only and must never be made permissive by configuration migration alone. [POLICY execution contract](../prompts/OKS-06H-POLICY.md) defines bounded delivery and acceptance. #70 remains operational acceptance; no production Vault writes, real secrets, paid calls or provider provisioning are authorized by this decision.
