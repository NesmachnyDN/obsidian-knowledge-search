# ADR-0009 — Optional local stdio bridge for Advanced execution

**Status:** Proposed for independent OKS-05B review (not an accepted production backend). **Parent decision:** accepted ADR-0006, opt-in Advanced profiles. **Scope:** lightweight health and supervised lifecycle **only**. **Base:** `990d82c11162e88701284b2af8469163480d26f8`.

## Decision and rationale

Choose an explicitly configured **External Backend / local stdio** profile for subsequent bounded Advanced experiments. The default plugin continues shipping only the Standalone assets; it starts no Python process, listener, model, runtime provisioning, downloads or network requests. The opt-in local Python environment belongs to the operator and is never an implicit installation prerequisite. A deliberately small TypeScript bridge communicates with an explicitly trusted local Python interpreter and entry through private stdio pipes. No TCP listener, discovery, authentication secret or remote host appears. Private parent-held pipes bind the transport to the specific child, but **do not establish a security boundary against a compromised same-user host or a malicious explicitly selected executable**.

Bundled Advanced is not selected in 05B. The pinned BGE-M3 candidate weights alone are 2,271,145,830 bytes; no independently validated Obsidian-compatible WASM/ONNX binary, tokenizer/weights parity, bundled license and runtime dependency closure, cancel/resource isolation or package-size approval exists. Do not silently distribute Python or its dependencies under the plugin. Re-evaluate only after empirical evidence, explicit runtime distribution decision and actual resource tests.

## Versioned health-only wire

This 05B bridge reuses the **existing Python v2 health-only experiment** (`engine/persistent.py`) without reinterpreting its envelope as a retrieval protocol. Parent sends exactly one bounded UTF-8 LF-terminated JSON object `{"version":2,"id":"<random 48-hex nonce>","method":"health"}`. The local Python probe rejects malformed/duplicate keys, unknown versions and extra fields. Its reply uses canonical compact encoding `{"version":2,"id":"<same nonce>","ok":true}\n`. The TypeScript bridge requires that exact canonical response, no extra stdout bytes, and one outstanding health operation (1024-byte response, 4096-byte discarded stderr budget, 4-second deadline). No source path, content, query, typed Property, credential, embedding vector or index identifier is sent. Future 05C–D **must create and cross-language test a separate strict production evidence/search protocol** with canonical SourceVersion/ParsedBlock/SourceLocator/Chunk/EvidenceHit semantics, rather than expanding the health-only v2 probe implicitly.

## Execution, trust and failure handling

An operator must explicitly select `local-stdio`, enable it, and supply two absolute trusted local paths. All filesystem path components are checked without following symlinks; the binary/source must be regular, single-linked files of bounded size, owner root/current user and not world writable; owner-controlled group-writable paths are admitted only for the caller's own UID/GID. In a **verified single-UID rootless Linux namespace**, system paths owned by unmapped host UIDs can appear as overflow UID 65534: these paths are admitted only if neither group nor world writable. This remains a same-user trust policy, not a multi-user security sandbox; interpreter must be executable. This is a **same-user trust policy** and preflight, not a race-free inode-pinned execution or OS sandbox. A malicious same-user writer could replace trusted paths between checks and spawn; a stronger OS policy is a future security gate. No path is taken from a query or Vault document. The child starts with `-I -B`, controlled minimal environment, `shell:false`, separate process group and private pipes; unexpected exit, timeout, invalid frame and too much stderr all invalidate transport health. Stop/disable/unload cancels the handshake and terminates the owned process group (TERM followed by bounded KILL), preserving Standalone's committed generation.

Settings schema 3 migrates existing schema 2 with Advanced **disabled** and retains the native Standalone settings and legacy manual probe. Advanced failure is reported by bounded typed code only; default diagnostic export must not expose an interpreter path, raw content or stderr. `advancedTransport: {profile,status,error,transportOnly:true}` is informational, never search/index/model readiness. Even a verified health exchange leaves **dense and hybrid unavailable**, with explicit `CAPABILITY_UNAVAILABLE` and `executedMode:none`. The authenticated canonical source/evidence contract and release-required resource controls are **not implemented** in this slice.

## Gates and residual risks

- Explicit opt-in, disabled default, no Python startup in package-only host, real desktop, no listener and offline isolated namespace; negative framing/nonce, worker crash, cancellation and restart tests.
- Heavy extraction and BGE inference **must not run** through this lightweight health channel without a separate bounded Linux cgroup v2 admission/whole-tree resource supervisor, verified model artifacts and selected document protocol. Prior 03A/03B synthetic cgroup experiments are reference evidence, not this bridge's runtime admission.
- Hostile concurrent same-user executable swaps, OS-wide process interposition, Python script import security, keyless publisher authenticity and distribution/runtime permission remain unaccepted. A selected trusted backend is explicitly local but not an OS sandbox. Never send private material in public reports.
- OKS-05B does not satisfy Advanced CAP-02/04/05 or MVP Gate B. Follow independent exact-HEAD full-diff review/CI and only then conditional squash merge.
