# ADR-0012 — Opt-in Cloud.ru BGE-M3 embeddings without cloud document processing

**Status:** Proposed (maintainer-selected target, 2026-11-23; independent review/merge pending).
**Scope:** optional Advanced embedding provider; it does not replace the accepted offline MVP gates.
**Related:** ADR-0006 (Standalone/Advanced boundaries), ADR-0010 (embedding identity, local index and portable vectors), ADR-0011 (local Docling/extraction cache), CAP-04/05/08/10/14.

## Context and measured integration evidence

Cloud.ru **Evolution Foundation Models** offers an embedding API with model identifier `BAAI/bge-m3`. A **manual, synthetic, single-request** test from the maintainer's Linux ZenBook succeeded: HTTP 200, 1024 finite dimensions, L2 norm ~1, 19 prompt tokens reported, ~1 second wall time. This validates *basic* endpoint/API connectivity only. It does **not** prove exact parity with locally pinned BGE-M3 weights/tokenizer, fixed upstream revision, stable provider behavior, vector quality, RAG accuracy, throughput, cost under bulk load, or production/plugin integration. No personal Vault was sent for this test.

The user selected Cloud.ru to avoid buying GPU hardware for occasional embedding generation, while keeping the authoritative Obsidian Vault, Docling/OCR, parsed-document cache, vector cache and search index **local**. Cloud.ru Foundational Models is the **only** intended external compute here. Do not create or require GPU VMs, Managed RAG, managed vector DB, S3 or cloud Docling. Other external LLM/RAG generation models are outside this ADR and not required for document retrieval.

## Decision

1. **Two explicit BGE-M3 execution modes.** Retain `local-offline` using verified local pinned model weights as the mandatory Advanced MVP implementation. Add a separate **disabled-by-default** `cloudru-api` embedding adapter as a post-MVP optional execution profile. Selection is explicit and visible; no automatic network fallback from local Docling, local BGE-M3 or search, and no silent downgrade from requested dense/hybrid to lexical. Failure returns a typed capability/provider error with separate recovery path.
2. **Fixed boundary:** all PDF/DOCX/scan parsing, local RU/EN OCR, original source metadata/provenance, chunking, embeddings cache lookup, SQLite/embedded vector indexing and RRF happen **on the user's machine**. Only canonical, user-authorized **embedding-input strings** (including their contextual prefixes) are transmitted over TLS to the BGE-M3 API, with the minimum provider-required request fields. Never upload source binary files, the Vault, local SQLite, full parsed-document artifacts or collected credentials.
3. **Consent and classification:** zero egress by default. Require explicit per-Vault *and per allowed scope/source category* opt-in before sending any text; deny unclassified/secret/proprietary/corporate documents unless permitted by their information-handling policy. Explain that embedding inputs contain document excerpts and contextual headers and are **not anonymized**. Provide preview/confirmation for initially enabled scope; allow revocation, offline disable and audit metadata. Lack of consent results in no cloud call, not a forced cloud upload.
4. **Credentials:** access Foundation Models using a scoped **service-account API key** in a per-user private secret store, not a personal global key or repository setting. A proof-of-connection used a file in a private configuration directory with mode 0700 and key file 0600 on Linux; this is **filesystem permission protection, not encryption**. Implementation must support key rotation/expiry, reject unsafe permissions/symlinks, never echo values or include keys in process arguments, exception text, diagnostic exports, PRs, scripts, Git, chat or telemetry. Use runtime-only injection/read through a bounded provider adapter. Do not change, print or re-upload the existing operator-managed secret.
5. **Provider and index compatibility:** request `BAAI/bge-m3` from the Foundation Models embeddings endpoint `https://foundation-models.api.cloud.ru/v1/embeddings` (verified in the synthetic smoke). Confirm response shape, 1024 dimensions, finite components, L2 norm, provider model identifier, input chunk count and usage metadata. Store provider namespace/endpoint, observed model identity, explicit serialization profile, numeric encoding and validated output probe fingerprint in a **separate, versioned cloud embeddingSpaceId**. A matching model name, dimensionality and normalized norm are **not** proof that remote and local spaces are equal. Do not mix cloud/local vectors or port them across runtimes until independently compared on a fixed RU/EN technical corpus with pinned identity and tolerance policy. When provider changes weights invisibly or parity cannot be established, isolate/rebuild its vector generation rather than silently reusing incompatible cached entries.
6. **Cost control:** track actual `usage.prompt_tokens`, request count, retry count, per-source/chunk cache hit rate, estimated currency spend and daily/monthly per-operator ceilings. Implement a **local hard stop** (admission check) on request/token budgets rather than relying only on cloud billing alerts; price is a configurable dated input, not a hard-coded truth. Enforce max batch payload, rate limit, concurrency, timeout, cancellation, bounded exponential retries and safe checkpoint/resume to prevent unintended repeated charges. Never claim the provider guarantees exact cost at the estimate. No full 1.5 GiB indexing until explicit authorization and privacy/cost preflight.
7. **Reuse and portability:** computed vectors are persisted in the local content-addressed embedding cache, reused for identical effective inputs, then placed in private local vector index. When compatible and explicitly authorized, vectors (not texts) may participate in ADR-0010's optional Yandex Disk immutable-artifact export. Cloud provider identification and model drift checks are prerequisites for multi-host reuse. A novel search query still needs a compatible selected query encoder.
8. **Operational safety:** Cloud.ru outages, expired key, quota, cost cap or internet loss must not break Standalone or local offline Advanced. If the user explicitly requests cloud dense/hybrid and provider readiness is absent, report an error/status rather than mislabel lexical-only execution. No global cloud access, no direct key use in the browser renderer, no default listeners and no remote Docling.

## Options not selected

| Option | Status |
|---|---|
| Cloud.ru Managed RAG / remote vector DB / GPU VM | Rejected as the default; index and data remain local. |
| Cloud Docling/Docling Serve | **Rejected**; ADR-0011 sets local-only extraction. |
| Cloud provider as mandatory MVP dependency | Rejected; would violate independently tested offline Advanced gate. |
| Assume cloud and local BGE-M3 are interchangeable | Rejected until fixed-corpus numerical/quality and identity validation. |
| Explicit opt-in cloud embeddings with local caching/indexing | **Selected** as target post-MVP capability. |

## SDD delivery and acceptance

**OKS-05D:** preserve the local BGE-M3 implementation and source-aware chunk/embedding identity and index profile. Do not inject a cloud requirement into 05D/05E or a currently reviewed candidate. **OKS-06E (after OKS-05E)** is the separate Cloud.ru provider bounded slice, after independent ADR review.

Positive/negative acceptance: synthetic 1024-vector contract; local/offline profile unchanged; explicit consent required before any network egress; unauthorized scopes and Vault docs not transmitted; invalid/empty/error/rate-limited responses, network outage and rotated keys fail clearly; measured capped batches/retries, token-cost enforcement and zero duplicate calls on identical cache hit; model drift/parity mismatch isolates index space; secrets absent from artifacts/logs/test output; revoke/disable restores offline behavior and keeps last compatible generation, with no hidden fallback. Use only synthetic fixtures until separately authorized.

**No new cloud services, key reads, paid batch runs, source uploads or bulk indexing are authorized by this ADR.**
