# ADR-0025 — Search-first delivery and bounded ownership simplification

**State:** Proposed for independent DOCS_ONLY acceptance. Maintainer direction following the architecture scope and complexity audit, 2026-11-28. Refines ADR-0023/0024 delivery order only; preserves all CAP/AC, security and profile gates. No runtime acceptance.

## Evidence and decision

The audit compared production baseline 7994fdd47f976ebb3364f0458cd59c24b556479b and PR #155 candidate 8d96c7b12f393b40e5a9b9a17cea4f8ffe2f8452. ADR-0024 was delivered separately by #156. Historical Basic-only Linux Gate A (#44) and bounded local graph (#104) acceptance remain valid for their recorded scopes. Native hard scope is not cumulatively accepted (#149); unified attachment retrieval (#111), read-only role policy (#78/#79) and actual scoped generation (#70) remain open. The audit ran 122 focused synthetic tests on the candidate with no failures; this is not full regression or release evidence.

Choose targeted decomposition and simplification, not a rewrite. PR #155 disposition: **SIMPLIFY_BEFORE_CONTINUATION**. Keep the candidate Draft and preserve the useful source seal, source identity/admission distinction, bounded ownership and regression evidence. Review [the earlier B-07 finding](https://github.com/NesmachnyDN/obsidian-knowledge-search/pull/155#issuecomment-7232460113) and [the later approval](https://github.com/NesmachnyDN/obsidian-knowledge-search/pull/155#issuecomment-7233606836): the audit found conflicting acceptance evidence at the same stated HEAD, not a newly reproduced defect. Reconcile actual refs and evidence with an independent explicit disposition before any continuation or delivery. Green CI alone does not resolve a finding.

## Dependency order

- P0: resolve conflicting acceptance evidence; independently accept a bounded ownership/completion design before editing the affected production contour; implement only the smallest justified simplification, then complete native hard scope across all paths and preserve/revalidate Basic. Reconcile read-only effective policy and historical lifecycle consumers with equivalent or stronger denials before removal. Complete role-specific prerequisites before using the affected role; do not make AI policy or enrollment a Basic prerequisite.
- P1: prioritize one canonical extraction/indexing/evidence/retrieval pipeline and a usable local PDF/DOCX content-search vertical with Markdown and attachments in one result set. Use the minimum compatible registry/cache work and qualified reuse; select adapters via existing format-specific evidence/benchmarks. Preserve original/linked-card navigation, truthful coverage, freshness, scope, resource limits and per-format/platform Gate C. Continue Office and other format families incrementally; full breadth and managed delivery remain required for a full-profile claim, not a prerequisite for lexical RAG.
- P2: scoped lexical generation/RAG and conversational chat on the accepted common retrieval foundation, with relevant effective policy, automatic corpus, provider/role and actual-host acceptance. Independently accepted Markdown-only scope can remain explicit; unclaimed formats, dense, hybrid, reranking and graph are not Gate B-Generation prerequisites. Further format work can proceed in independent bounded slices after the initial document vertical.
- P3: optional semantic/dense, hybrid, reranking and graph enhancements, portable artifacts and remaining cache/runtime/platform breadth, with one active compatible dense generation. Retain historical graph acceptance; no requirement to redo it solely for reprioritization. Address scale and incremental maintenance whenever required by the claimed vertical, rather than deferring essential bounds or freshness. Retain Android-first mobile direction and separate platform/format claims. #80 remains optional deferred.

This order supersedes the earlier Markdown-RAG-first scheduling in ADR-0023 and the rebaseline contract; it does not change the acceptance partition or historical decisions. Keep coexistence fences until equivalent or stronger safety is independently demonstrated. No mandatory provider, producer, model runtime, source write or extra retrieval engine.
