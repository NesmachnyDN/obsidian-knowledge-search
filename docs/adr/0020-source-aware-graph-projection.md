# ADR-0020 — Source-aware local graph projection and bounded context expansion

Status: proposed for independent SDD design acceptance (OKS-06B.1); no capability/adoption claim. Authority: ROADMAP 06B.1–4, SPEC CAP-01/06/07/08/09/10/11, ADR-0008/0015/0018/0019. Base ac433dcfd0ae27c389e1466af4966d0baaaf3458. Obsidian originals remain the only knowledge authority.

## Decision and scope

Derive a read-only graph from the authenticated local Standalone generation. Reuse SourceVersion, typed Properties, canonical source locators and source lifecycle; do not create a graph database, second index authority, new knowledge metamodel, inferred fact store, source writes or AI calls. Initially Markdown only. Existing wiki-link metadata filters and basic text search remain unchanged and do not depend on graph availability. Attachments and ownership under ADR-0017/0019 require separate verified discovery; ordinary graph edges never grant ownership or disclosure.

## Versioned configurable mapping

The graph is disabled by default. A reviewed version-1 mapping is explicitly configured locally (no personal card schema hardcoded). Strict validation, canonical serialization and domain-separated SHA-256 bind the mapping revision. Proposed maximum: 16 KiB UTF-8, 32 relation definitions, 64 allowed type values, 64 status values. Values and property keys are exact case-sensitive strings within existing typed Property limits; do not coerce numbers, dates, null or booleans to identifiers. Mapping contains:

- Optional card-type, business-identity, aliases and status Property keys. Path is always the canonical local source identity; business IDs and aliases are lookup indexes only, never replacements for path/version. Only unique, explicitly authored nonempty string identifiers/aliases can resolve. Duplicate or colliding identifiers are ambiguous even if one competitor is outside the selected query scope. Missing type/status is explicitly unknown. Only exact configured status strings may be labeled **author-declared**; no independent truth/confidence inferred.
- A relation rule has a unique relation ID, exact Property key, direction (author-to-target or target-to-author), target encoding (exact vault-relative Markdown path, exact business ID, or explicit wiki-link), optional allowed source/target card types. Scalar string or list of strings only; invalid member or unsupported Property syntax makes that rule incomplete, never silently coercing or dropping an item. Duplicate authored edges retain their separate locators or deterministic deduplication with all anchors; no invisible semantic inference.
- Wiki-link resolution in v1 uses exact canonical path, optionally adding the Markdown suffix only when unambiguous, or a unique exact basename/explicit configured alias in the complete local source catalog. Aliased display text is not target identity. Reject ambiguous, unresolved, unsafe paths, external URLs, unsupported fragments/embeds and malformed syntax; do not guess relative paths or case, dereference URLs, or use Obsidian's best-effort first match. Explicit body links outside fenced code and frontmatter can form navigation-only edges. They are excluded from typed expansion, and property rules do not turn unconfigured links into semantic relations.

## Projection contract and lifecycle

A graph snapshot binds schema/algorithm version, root identity, exact lexical generation ID, canonical mapping digest, complete source-version set and deterministic graph identity. Nodes reference source path + SHA and optional typed labels. Each directed edge carries rule/type, exact endpoints and both source versions, author/source version and original block ID/line/byte locator(s). The edge means “this source asserted this relation”; it is not a verified real-world fact. Unknown/malformed Properties or unavailable provenance must not produce asserted edges. Navigation-only links are distinctly typed. Report coverage counts for unresolved/ambiguous/invalid/unsupported/rejected relations; limit errors are explicit, not truncated success. Do not store raw source text again in the projection.

Keep one derived projection per current lexical generation + mapping, initially rebuildable in memory from authenticated immutable CURRENT (no second persistent graph store or independent writer). Canonical sorting and deterministic resolution; bounded work in cooperative units or the existing worker boundary, with no new unbounded UI-thread scan. Nodes <= existing BOUNDS.sources; authored edge count <= 8192; canonical projection <= 4 MiB. Incremental publication reuses the existing generation/lifecycle owner and exact source set. Disable, mapping edit, source event, pending reconciliation, generation replacement or retirement invalidates graph reads before observers; restart derives again from current authenticated lexical data. No graph publication from degraded, uncertain or retired generation. A new/renamed/deleted source can change ambiguity for other nodes; resolve against the complete permitted catalog, not only changed edges. Revalidate exact source membership/versions before graph exposure/expansion, including identity competitors. Existing locally authorized indexing catalog may supply only identity/version facts needed for resolution; selected query scope still gates every exposed node/edge/excerpt. If complete current resolution cannot be verified within local authorization, fail closed; do not read outside permitted roots or widen the selected scope.

## Query contract (06B.3)

Explicit opt-in graph expansion of an already verified lexical result; no default graph traversal and no silent fallback or change to existing lexical mode. Use a bounded operation-local host lease pinned to root, generation, mapping, exact original scope, source versions and request/deadline. Reuse existing scope/retrieval/evidence and lifecycle authority, not a second controller. Traversal is deterministic and cycle-safe, follows configured type/direction, never crosses any scope or version boundary (including edge author). Initial limits: depth 0–2, fan-out <=16 per node, <=32 distinct expanded candidates, <=50 total returned hits, <=16 KiB context before any existing tighter role/input/token limits. If a configured bound would exclude a valid required expansion, report a typed GRAPH_LIMIT with no implicit unexpanded success; user can explicitly retry unexpanded or narrower. For a chosen limit and top-K, report coverage, executed mode and deterministic ranking; preserve original ranks separately. Graph paths carry authored edge anchors and original evidence, not synthesized excerpts or invented spans. Reauthenticate sources and exact locator before display/navigation/role preview/dispatch/publication; all graph constituents are included in ADR-0019 eligibility and existing one-shot consent when a separately admitted AI role uses expanded evidence. No automatic cloud work, no hidden fallback, and no provider access to raw graph metadata by default.

## Alternatives and reuse

Use the existing parsed/source evidence contracts, deterministic typed Property parser, metadata anchor verification, bounded single-flight queue and private generation storage; no prior application graph DB or governance model. A separate persistent graph store adds independent consistency/recovery obligations without a measured need at the current corpus bounds; rejected for v1. Best-effort Obsidian metadata-cache resolution alone is insufficient as freshness and ambiguity authority. Full projection rebuild is acceptable within measured budgets; optimize incrementally only with demonstrated need and correctness parity.

## Preregistered acceptance (06B.4; not yet measured)

Freeze generated RU/EN corpus, mapping, queries, ground truth and immutable split manifest before held-out execution; target at least 128 notes (plus 512-note stress), 40 held-out queries balanced RU/EN and graph-required vs ordinary, positive/negative directed relations, duplicates/aliases, unresolved links, cycles, stale edits/rename/delete and restrictive policy. Compare identical lexical baseline with explicit graph expansion, report per-query Recall@10, nDCG@10, MRR@10 and relation/path precision/recall, source/locator correctness and failures; never combine unavailable AI profiles with successful lexical results. Gates: 100% exact valid authored edge/locator precision on fixture, zero scope/egress/critical stale/false relation violations, graph-required Recall@10 improvement >=0.10 absolute and nDCG@10 nondecrease vs baseline, ordinary-query nDCG@10/MRR@10 degradation <=0.02 absolute; no mandatory exact-ID regression. Report paired deltas and all exclusions, do not tune thresholds on held-out data. Provisional reference-host budgets to test: <=4 MiB projection, <=64 MiB incremental peak process RSS, p95 projection <=500 ms at bounded 512 notes excluding authenticated source I/O, p95 added query latency <=250 ms at 128 notes including graph freshness checks, UI event-loop p95 <=50 ms during projection. Report actual source I/O, CPU/RSS/disk, cold/restart, cancellation, rollback and per-accepted-role API tokens/cost separately. Failure leaves graph unaccepted, not a reason to weaken Gate A. Real offline Obsidian and supported CLI checks for claimed platform, independent exact-HEAD review and cumulative 06B.4 required. No production source, real provider or deployment authorization.
