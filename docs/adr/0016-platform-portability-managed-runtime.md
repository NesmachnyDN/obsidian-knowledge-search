# ADR-0016 — Platform portability and managed optional document runtime

**Status:** Proposed; product-owner direction confirmed 2026-11-25; independent SDD review pending.
**Scope:** Future packaging, platform adapters, onboarding and feature-specific acceptance. No implementation or release authorization.
**Related:** ADR-0008, ADR-0009, ADR-0011, ADR-0015; CAP-15/16.

## Decision

- One logical OKS plugin, stable identity, shared contracts and UX. Install the lightweight autonomous core by default. No edition picker, mandatory onboarding, provider setup, download or elevated permission on first launch. Basic search starts after workspace readiness.
- Optional document runtime is offered once in context on the first explicit unsupported PDF/DOCX/OCR processing request, or proactively from Documents settings. Do not prompt on merely detecting attachments, startup, sync or every failed attempt. Decline/dismiss leaves core operational; explicit retry/settings remains available. Show platform support, components, download/disk estimates and local processing boundary before the single affirmative action. Resume the intended operation after verified readiness when still authorized and current.
- Target one user action to acquire the managed runtime on supported desktop hosts. No terminal, separately installed Python/Docker/Ollama, manually entered paths, dependency resolution or model setup. Bundle or provision an isolated pinned Python engine, Docling, required tokenizer/layout/table artifacts and RU/EN Tesseract assets; discover and validate compatible installations automatically. AI APIs remain independently configured; installing document processing never implies AI consent or readiness.
- Distribution is a hard gate: Obsidian Community Directory developer policies prohibit plugins installing/updating themselves or their dependencies. Do not implement a self-updater or downloader in a directory-distributed plugin. Evaluate compliant external one-action installer/package manager, prebundled reviewed assets where allowed, or an approved distribution route; verify policy before implementation. External installer owns provisioning/update/removal; plugin owns capability detection and verified job lifecycle. Do not silently launch installers, bypass OS security prompts, or claim truly unattended installation where mandatory platform consent intervenes. If one-action UX is infeasible in a channel, report it and seek a product decision before release. References: [developer policies](https://docs.obsidian.md/community-directory/developer-policies), [mobile development](https://docs.obsidian.md/Plugins/Getting%20started/Mobile%20development).
- Use signed/verified versioned artifacts with pinned hashes, publisher identity, license/SBOM review, platform/architecture selection, authenticated downloads, disk/memory preflight, staged atomic activation, cancellation, rollback, repair and safe uninstall. No arbitrary shell strings, unverified executable, implicit privilege escalation or source data upload. Update only through an authorized distribution mechanism; keep a previously verified compatible runtime when safe. Failed or missing runtime never disables basic search; no silent format downgrade.
- Target Linux, Windows and macOS desktop, and Android and iOS/iPadOS mobile. Linux is the current reference; every platform/architecture requires independent evidence, not a manifest-only change. Android tablet is the first mobile priority. Share pure parsing, lexical retrieval, typed Properties, evidence and lifecycle contracts; isolate filesystem, hashing, storage, worker/process supervision, transport and UI adapters. Preserve exact fresh evidence, scoped reads, transactional visibility and host-local disposable derived data. Re-evaluate storage and threat model on each platform; no downgrade of existing Linux security.
- Mobile Obsidian has no Node/Electron API and uses a different adapter. Remove unconditional desktop imports from the mobile load path, prefer Obsidian Vault/MetadataCache and Web APIs, and validate mobile-local transactional storage, worker/cooperative scheduling, suspend/resume, app kill, low memory, battery, touch UI, sync and offline operation on physical devices. Keep desktop-only manifest until mobile build is proven. Platform-specific CLI obligations apply only where Obsidian actually supports CLI; equivalent in-app lifecycle/API checks remain mandatory.
- Mobile first target is offline Markdown/Properties search and verified source navigation; optional AI API roles are separately accepted per platform with unchanged consent and model/index identity rules. Do not require local LLM, Python, Docker, Ollama or Docling on Android/iOS. Native mobile Docling/OCR is not a committed initial capability; assess feasibility and alternatives in a later design gate. Desktop-created parsed text may not be silently synced to mobile; a portable parsed-cache or remote document processing would change ADR-0011 and needs separate explicit approval, security design and acceptance. Existing portable vector transport is not a parsed-text transport. No remote parsing or unapproved LAN/provider routing is authorized.
- Gate A applies per supported platform; Gate B per claimed AI role/platform and Gate C per claimed format/platform. Public release only advertises verified combinations; mobile-only constraints never force extra desktop dependencies. Existing Linux Gate A evidence is retained, not generalized.

## Acceptance and sequencing

See OKS-06F.1–06F.5 in the roadmap. Design first; measure clean-install, offline startup, missing/failed/declined optional install, network interruption, tampering, version mismatch, resource exhaustion, rollback, restart, uninstall and no-egress behavior. Test real Linux/Windows/macOS hosts and Android/iOS devices as applicable, including ARM/x86 where claimed. Freeze platform-specific support matrix and budgets before acceptance. Separate private distribution and Community Directory compliance decisions; no claim of directory approval. No production Vault operations, downloads or installation authorized by this ADR.
