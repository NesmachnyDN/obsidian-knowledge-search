# ADR-0017 — Extensible local multi-format attachment extraction

**Status:** Proposed; product-owner requirements recorded 2026-11-25; independent SDD review pending.
**Scope:** Future document processing, indexing and source navigation; no implementation or production processing authorization.
**Related:** ADR-0011, ADR-0015, ADR-0016; CAP-02/03/06/08/09/10/13/15/16/17.

## Product requirements and boundaries

Every format in the required desktop coverage matrix below must have a tested path for actual content extraction, indexing, search and navigation to its original file. Preview/rendering inside OKS, editing, running macros, executing formulas, rendering diagram source or launching arbitrary file content are not required. Basic-only Gate A remains independent; full document profile acceptance requires all required formats, not merely PDF/DOCX. Original Vault and cards are authoritative. Recognized content must be searchable without an AI provider; enabled and accepted AI retrieval roles must be able to consume the same authorized evidence through canonical chunks. No separate knowledge store, no compulsory extra runtime for core, no remote parser or silent source-data sync. Mobile format claims remain separately gated by ADR-0016; investigate mobile-safe adapters for broad coverage without forcing Python/Java/desktop runtimes.

## Required coverage and candidate adapters

| Family / required formats | Content and useful provenance | Candidates (evaluate, not selected dependencies) |
|---|---|---|
| MD, TXT | Text, headings where present, lines; UTF-8 and tested common legacy encodings (including Windows-1251) | Existing native Markdown; portable text adapter |
| PDF | Native text, pages, headings/tables where verified, scan OCR RU/EN | Existing Docling/Tesseract; compare Tika/PDFBox where useful |
| DOC, DOCX | Paragraphs, headings, tables, available headers/footers | Docling for structure; Tika/POI for legacy and fallback; LibreOffice if justified |
| XLS, XLSX | Sheet names, cell text, numeric values, cached formula results and formula text distinguished; row/cell references | Docling, Tika/POI, dedicated spreadsheet readers |
| PPT, PPTX | Slide text, titles, tables, accessible speaker notes; slide references | Docling, Tika/POI; LibreOffice if justified |
| VSDX (owner wrote VSXD; interpret as Visio VSDX, detect actual bytes) | Page, shape labels, text, available source/target labels or explicit connectors when verified | Tika VSDX extractor / POI XDGF; safe OOXML adapter only if needed |
| drawio | All pages, shape/edge labels, user-object text and explicitly represented endpoints; compressed and plain mxGraph XML | Bounded local XML/mxGraph decoder using documented format |
| PNG, JPG, JPEG, BMP | RU/EN text in screenshots, diagrams and scanned images; OCR confidence/geometry where available | Tesseract, Docling image pipeline; extract embedded draw.io source only when verified |
| Mermaid, UML | Source text, labels, entities and explicit relations where recoverable; fenced blocks in MD and standalone .mermaid/.mmd/.uml/.puml/.plantuml (text); detect other UML serializations, e.g. XMI, separately | Native text and bounded specialized adapters; no external includes, rendering or execution |
| MSG | Subject, sender/recipient/date, plain or sanitized HTML body, supported embedded attachments with parent identity and bounded recursion | Tika/POI Outlook extractor, Docling email support or maintained MSG reader |

Additional backlog candidates: CSV, TSV, JSON, XML, YAML/YML, HTML/HTM, RTF, ODT/ODS/ODP, EML, SVG, TIFF, WEBP, VSD, XMI, PDF/Office embedded images. Prioritize by actual usage and measured feasibility; no claim of blanket support for every detected MIME type. Review embedded-image OCR coverage per Office/PDF format and report limitations explicitly. Purely visual semantics without text (e.g. an unlabeled topology) are not guaranteed by OCR; richer vision/diagram understanding is a separate opt-in design and acceptance decision. No inferred graph relationships become confirmed Vault facts.

## Architecture and adapter selection

- Use a versioned allowlisted extractor registry: stable adapter ID/revision, detected MIME/signature and supported extensions, supported platform/profile, capabilities (text/structure/OCR/embedded content), required assets, resource limits, provenance level and typed readiness. Dispatch by verified bounded content detection, not suffix alone; ambiguous/mismatch/corrupt/encrypted/unsupported cases fail explicitly. No untrusted executable plug-in loading. Adding a reviewed format adapter must not require changing search/ranking/UI contracts.
- Prefer existing maintained libraries. Docling remains candidate for high-quality structural formats; compare its exact pinned-version capabilities with Apache Tika (broad detection and text/metadata, Java runtime) and Apache POI, lightweight portable adapters, and LibreOffice conversion only where justified. Current upstream Docling docs list legacy DOC/XLS/PPT via LibreOffice; do not infer availability in installed version. Tika's detection or metadata coverage is not evidence of actual textual extraction. Measure coverage/quality, provenance, RU/EN, footprint, CPU/RSS/latency, licenses/SBOM, vulnerability surface and packaging on supported hosts. Select minimal dependencies and explicit per-format route in a reviewed decision. No Java/LibreOffice requirement for basic core; if selected, managed optional runtime provisions dependencies together in one user action, not separate manual installation.
- Normalize each adapter into existing ParsedDocument/ParsedBlock, Chunk and EvidenceHit contracts; evolve those versionedly when needed (e.g. sheet/cell, slide, shape, image region, message attachment chain). Native locator if authenticated, otherwise honest file-level locator and extraction provenance; never fabricate original spans, structural anchors or completeness. OCR text is recognized derived evidence, not byte-exact original text. Distinguish source text, metadata, OCR and contextualized input. No silent downgrade or double-counting fallback output; selected fallback routes and partial coverage visible. Extend ADR-0011 cache identity to every extractor, version, exact options/assets and mapping; compatible cache reused across chunk/index/model changes.
- Within explicit allowed Vault scope, discover attachments through file enumeration and resolved card links/embeds; maintain reverse card links, deduplicate source extraction by verified identity/version (multiple cards can refer to one file), preserve authorization per source, handle orphans by scope policy, reconcile create/modify/rename/delete and link changes including missed sync events. Card titles/Properties may provide separately labeled context, not replace attachment content or inherit authorization implicitly. Search results expose original file, verified excerpt and related authorized cards; open original via safe Obsidian/OS navigation where supported, at least return verified card/link/file path when host cannot open a type. No custom preview required. No source modification. Once optional runtime is enabled, bounded incremental extraction/indexing is automatic within chosen scope, not manual per-file administration; no auto-install from attachment detection. Show pending/ready/partial/empty/failed/unsupported/locked/disabled and coverage counts by format; no silent omissions.
- Use the same canonical content in autonomous local lexical index and optional accepted dense/hybrid, reranker and generation flows. Reconcile original bytes/scope before exposing hits, suppress stale/deleted evidence, no remote parse and no provider egress merely from enabling extraction. Preserve single active dense space and independently accepted role gates. Keep derived extracted text and indexes host-private; portable vectors do not replace original evidence.
- Treat all files as untrusted. No macros/scripts/formula evaluation, active HTML, network fetch, remote XML entities, external diagram includes or embedded executable execution. Bound ZIP/XML expansion, nested archives/messages, path traversal, decompression ratios, output/page/cell/pixel counts, jobs, CPU/memory/disk/time; isolate parser jobs, cancel whole process tree and recover without source writes. Encrypted/password-protected and malformed files report explicit status; no password bypass. Redact diagnostics, pin verified artifacts and review licenses/security before selection.

## Acceptance and sequencing

OKS-06G.1–06G.5: design/benchmark first, registry and lifecycle integration next, family-specific implementation/acceptance, then cumulative full-profile Gate C across all required formats on each claimed desktop platform. Use generated representative RU/EN architecture documents, mixed Office tables/slides/notes, diagram labels and edges, compressed draw.io, screenshots/scans, MSG body/attachments, text encodings, duplicate links and negative/adversarial fixtures. Predeclare expected unique content tokens, provenance, coverage and performance bounds; prove content-only queries return the correct file and authorized card context, not merely filename/metadata; exercise accepted optional AI modes without requiring them for lexical. Measure missing-content and false-positive rate, OCR quality, resource and cache efficiency, incremental update, offline behavior, stale/delete/rename, crash/restart/rollback and installation/upgrade. Distinguish format support from platform support. Gate A and existing format behavior must not regress; public claims only for independently verified combinations.
